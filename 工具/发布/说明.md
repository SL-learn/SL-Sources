# 双平台地址渲染与双远端同步

## 一、为什么要这么做

GitHub 与 Gitee 的 raw 基址不同（一个 `raw.githubusercontent.com`，一个 `gitee.com/<个人地址>/<仓库>/raw`），把 GitHub 地址原样推到 Gitee 会让整个配置不可用。因此：

- 基址只在 `规则/平台地址.json` 定义一处；
- `地址.md` 与各 README 的地址块由渲染脚本生成，两平台并列、两侧内容一致；其余文档只写仓库内相对路径；
- `apps/tvbox/api_index.json`、`apps/tvbox/api_all.json` 按平台渲染，其余文件两平台完全一致。

强制条款见 `规范/仓库通用规范.md` 第 3.5 节（SYS-DIST-002 ~ SYS-DIST-008）。

## 二、目录

| 文件 | 作用 |
|---|---|
| `规则/平台地址.json` | 两平台基址（raw / 网页 / jsDelivr），唯一事实来源 |
| `地址模板.md` | 地址模板，占位符 `{{GITHUB_RAW}}`/`{{GITEE_RAW}}` 等，两平台共用 |
| `地址.md` | 渲染产物，两平台地址并列，两侧内容一致，勿手改 |
| `渲染.py` | 渲染上述产物与 README 地址块，并跑跨平台地址门禁 |
| `同步双远端.ps1` | 一条命令渲染并推送 `main` 与全部 tag 到两个远端 |

## 三、渲染（不推送）

```powershell
# GitHub 版（本地 main 常态就是这一版）
python 工具/发布/渲染.py --platform github

# Gitee 版（需要 Gitee 个性地址，用于拼 raw 基址）
$env:GITEE_OWNER = "<你的 Gitee 个性地址>"
python 工具/发布/渲染.py --platform gitee

# 只做门禁，不写文件
python 工具/发布/渲染.py --check --platform gitee
```

`渲染.py` 会：① 读 `规则/平台地址.json` 取两平台基址 → ② 调 `工具/源生成/生成.py` 重算 `apps/tvbox/api_index.json`、`api_all.json`（按 `--platform` 决定指向） → ③ 由 `地址模板.md` 渲染 `地址.md`，并把 README 地址块写入受管标记之间 → ④ 门禁（标记外不得出现写死的仓库绝对地址或另一平台域名；`地址.md` 必须含两平台基址且不把 451 路径当可用地址；README 地址块必须是最新）。

Gitee 版 `api_index.json` 的三条线路统一指向 `api_all.json`（64 站单文件）：Gitee 对 `apps/tvbox/std/api.json` 返回 451 内容审核，三条线路各自地址会有一条不可用。GitHub 版仍为三线路各自地址（SYS-DIST-009）。

> 注意：**不要在本地 main 上手动跑 gitee 渲染**，否则本地工作区会被 Gitee 版污染。Gitee 版只在推送前的临时 worktree 里渲染（由同步脚本负责）。

## 四、同步（渲染 + 推送）

```powershell
# 两个平台一起（默认）
powershell -ExecutionPolicy Bypass -File 工具\发布\同步双远端.ps1

# 只推 Gitee
powershell -ExecutionPolicy Bypass -File 工具\发布\同步双远端.ps1 -Only gitee

# 演练：只渲染和看计划，不推送
powershell -ExecutionPolicy Bypass -File 工具\发布\同步双远端.ps1 -DryRun

# 不推 tag（默认会推全部 tag）
powershell -ExecutionPolicy Bypass -File 工具\发布\同步双远端.ps1 -SkipTags
```

逐平台做的事：

1. 从本地 `main` 建临时 worktree（`%TEMP%\SL-Sync-<平台>-<随机>`），本地未提交改动不参与、也不会被污染；
2. 在临时 worktree 里渲染该平台版本；
3. 只提交 `地址.md`、`apps/tvbox/api_index.json`、`apps/tvbox/api_all.json` 与四个 README 的地址块；
4. 与远端 `main` 对齐：远端仅多出「`chore(双平台地址)`」开头的渲染提交时，用 `merge -s ours` 合并（树保持本次渲染结果）；出现其他提交则**中止**，交人工合并；
5. `git push <远端> HEAD:main` + `git push <远端> --tags`（**从不 force push**）；
6. 删除临时 worktree 与临时分支，本地工作区保持原样。

远端约定：GitHub 用现有 `origin`（https）；Gitee 用 `gitee`（SSH，`git@gitee.com:<个性地址>/SL-Sources.git`），首次运行会自动 `git remote add`。

## 五、Gitee 首次准备（SSH）

1. 本机已生成专用密钥：`C:\Users\SL\.ssh\id_ed25519_gitee`（ed25519、无口令短语），公钥为同目录 `id_ed25519_gitee.pub`。
2. `~/.ssh/config` 已加：

   ```text
   Host gitee.com
       HostName gitee.com
       User git
       IdentityFile C:/Users/SL/.ssh/id_ed25519_gitee
       IdentitiesOnly yes
   ```

   GitHub 继续走 HTTPS（`origin`），不受影响。
3. 把公钥全文粘到：Gitee → 右上头像 → **设置** → **SSH 公钥** → 标题填 `SL-Sources 镜像同步` → 粘贴公钥 → 确定。
4. 自检：

   ```powershell
   ssh -T git@gitee.com
   ```

   成功时返回到以 `Hi <你的Gitee用户名>!` 开头、含 `successfully authenticated` 的欢迎语（Gitee 不提供 shell，属正常）；返回 `Permission denied (publickey)` 说明公钥还没生效，检查是否粘全、是否粘到了 SSH 公钥（不是「部署公钥」）。
5. Gitee 侧建同名空仓 `SL-Sources`（**不要**勾选初始化 README / .gitignore / 许可证），公开仓，然后运行同步脚本。

## 六、验收

```powershell
# 门禁（两平台都要过）
python 工具/发布/渲染.py --check --platform github
python 工具/发布/渲染.py --check --platform gitee

# 线上实测（200 + 站点数/条数）
python 工具/源生成/校验.py --platform github
python 工具/源生成/校验.py --platform gitee
```

`校验.py` 会逐条比对索引、三条线路、`api_all.json`、`spider.jar`（含 md5）与 `cms.js`。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `缺少 Gitee 个性地址` | 未设 `GITEE_OWNER` | 设环境变量或用 `-GiteeOwner` 传入 |
| `Permission denied (publickey)` | 公钥未添加或加错位置 | 重新粘贴到「SSH 公钥」，`ssh -T git@gitee.com` 自检 |
| `Repository not found` | Gitee 仓库还没建 | 先建空仓 `SL-Sources`（不初始化） |
| `远端 main 存在非渲染提交，脚本拒绝推送` | 远端有人手动提交过 | 先 `git fetch gitee && git merge gitee/main` 人工合并后再跑 |
| 本地 `git status` 出现渲染改动 | 手动跑了非本平台的渲染 | `python 工具/发布/渲染.py --platform github` 还原 |
