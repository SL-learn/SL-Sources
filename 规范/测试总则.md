## 1. 测试对象与范围

### 1.1 测什么

| 层 | 内容 |
|---|---|
| 结构层 | 配置文件可解析、字段类型、必填项、`sites` 数量与 id 唯一性 |
| 功能层 | 站点加载、首页/分类数、分类下条目、详情字段 |
| 播放层 | 首片延迟、实测速率、码率、10 秒断流次数、能否取到可播放地址 |
| 稳定性层 | 多轮复测、间歇判定、超时与重试、挂起隔离 |
| 直播层 | m3u8/txt 首行 `#EXTM3U`、频道数与分组数 |

### 1.2 不测什么

- 不测播放器解码性能、投屏、弹幕、倍速等客户端功能。
- 不测上游内容的版权、画质主观观感、字幕准确性。
- 不把「接口 200」当成任何一层的通过依据。
- 不因「无法离线执行」直接判死 jar/py/js，必须按各自方式真跑或标「待模拟器」。

## 2. 结论三态与挂起

| 结论 | 定义 | 处置 |
|---|---|---|
| 可用 | 四层判据全过，且多轮复测按分册要求全通 | 进成品 |
| 间歇 | 部分轮次通过、部分轮次失败（非挂起） | 入观察池，禁止直接删除 |
| 不可用 | 全轮失败，或某层结构性为空 | 入观察池；连续 3 次全挂才提请永久删除 |
| 挂起 | 单源累计占用超 90 秒被看门狗终止 | 两轮均挂起才删除，并进《挂起源清单》 |

单轮失败不判死；全轮通过才记「稳定」，任一轮失败即记「间歇」（「通/挂/通」也不例外）。

## 3. 通用判据（四层）

### 3.1 结构层

| 项 | 通过线 |
|---|---|
| 配置解析 | `json.loads` 成功；顶层字段齐全 |
| 站点 id | 非空、唯一、只含小写字母数字下划线 |
| 必填字段 | `id` / `name` / `api`（或 `url`）/ `type` 均存在且类型正确 |
| 布尔字段 | 搜索开关一律写数字 `0/1`，不得写 `true/false` |
| 体积 | 单文件 ≤ 2 MB；站点数不超过分册上限 |

### 3.2 功能层

| 项 | 通过线 |
|---|---|
| 首页/分类 | 分类数 ≥ 1，分类名可读（不含 `�` 与连续拉丁乱码） |
| 分类下 | ≥ 2 个分类各取到 ≥ 1 条带 `vod_id`+`vod_name`（书源为书名+作者） |
| 详情 | 播放地址字段非空且可解析出至少 1 个「集名$地址」 |
| 搜索 | 关键词命中 ≥ 1 条，且详情可打开 |

### 3.3 播放层

对详情返回的首个播放地址实拉数据，不能只看状态码。

| 指标 | 采样方式 | 通过线 |
|---|---|---|
| 首片延迟 | m3u8 首个分片首字节；mp4 前 5 MB 首字节 | ≤ 3000 ms |
| 实测速率 | 首片/前 5 MB 下载速率 | — |
| 码率 | 主清单 `BANDWIDTH`，或分片字节×8÷`EXTINF` 时长 | — |
| 10 秒断流 | 10 秒窗口内继续拉后续分片，读超时/异常计 1 次 | ≤ 1 次 |
| 判档 | 速率 ≥ 码率×2 → 流畅；≥×1.5 → 一般；<×1.5 或首片 >3s 或断流 ≥2 → 卡 | 卡档单独成组 |
| 内容确认 | 首 100 KB 为 `#EXTM3U` / TS 同步字节 / `ftyp` / `FLV`，或 `Content-Type: video/*` | 必须命中其一 |

### 3.4 稳定性层

| 项 | 通过线 |
|---|---|
| 轮数 | TVBox 2 轮；小猫影视 3 轮；阅读 3 轮 |
| 轮间隔 | ≥ 60 秒 |
| 超时 | 首轮 10 秒，失败放宽到 20 秒；详情/播放按分册放宽 |
| 重试 | 单端点失败重试 2 次；GET 失败后允许 POST 回退 |
| 判定 | 全轮通过 = 稳定；部分通过 = 间歇；全挂 = 不可用 |

### 3.5 能力类型（四型，任何应用都必须先分层）

**红线：分类为空不得判失败。** 首页无分类、分类下无片，只能证明「这条源没有浏览入口」，不能证明源失效。凡因分类为空被判失败的，必须补测「直接搜索」路径后再下结论。同理，搜索无结果也不得推翻已通过的分类结论。

四型定义：

| 型 | 判据（缺一不可） | 处置 |
|---|---|---|
| 全功能型 | 分类有片 + 详情可进 + 播放/正文可取 + 搜索有结果 | 正常收录，排在全部源之前 |
| 仅搜索型 | 分类为空或无分类，但固定关键词搜索命中 ≥ 1、详情可进、播放/正文可取 | 收录；名称加本应用搜索图标（TVBox `🔎`，阅读沿用现有图标体系）；整组排到中后段 |
| 仅分类型 | 分类有片且可播，但固定关键词搜索 0 结果 | 收录（关闭搜索开关，TVBox 写 `searchable: 0`），排在仅搜索型之前 |
| 无入口型 | 分类与搜索都取不到内容，或装载/详情/播放任一环节失败 | 判失败，进观察池，不得留在成品占位 |

仅搜索型的可执行判定步骤（不得只判断「接口返回 200」）：

1. 固定关键词池：影视类 `庆余年,流浪地球,哪吒`；少儿类 `小猪佩奇,汪汪队,熊出没`；其他应用按分册给词，并在报告中写明实际使用词。
2. 逐个关键词调搜索接口，命中 ≥ 1 条即取**搜索结果第一条**。
3. 用第一条的 id 进详情，取播放地址或正文，取不到换第二条、第三条，最多 3 条。
4. 对首地址实拉数据：视频取 **≥ 100 KB 且魔数为 `#EXTM3U` / TS / `ftyp` / FLV 或 `Content-Type: video/*`**；阅读按**正文字数 > 0 且非错误页**。
5. 以上四步全过才记「仅搜索型」；任一步取不到真实内容，记该型失败并写明卡在第几步。

命名与排序：

- 仅搜索型名称只允许在**内容符号之后**追加搜索图标，不得前置、不得改写内容符号。
- 排序：全功能型 → 仅分类型 → 仅搜索型；同型内按播放速度档（流畅 → 一般 → 卡 → 无法测）。
- 使用说明必须固定写一句：带搜索图标的源没有分类页，直接搜索使用。

归类只取一层，依据写入报告「能力类型」列；同一源分类结论与搜索结论必须并列记录，不得互相覆盖。

## 6. 观察池（间歇源专用，禁止直接删）

### 6.1 固定位置

```
非公开域\记录\观察池\<应用>\
├── 观察池.csv          机器读的索引
├── 观察池.md           人看的结论与裁决请求
└── 备份\               摘出源完整原文，一条源一个 json
```

成人源观察池存放于非公开目录，结构相同，明细不进公开目录。

### 6.2 CSV 固定 13 列

`源标识key | 源名称 | 首次发现日期 | 首次测试时段 | 最近测试时段 | 最近3轮结果 | 累计轮次 | 失败位置 | 失败证据摘要 | 下次复测日期 | 当前状态 | 用户裁决 | 备份文件名`

- `最近3轮结果` 用 `/` 分隔，如 `通/挂/通`。
- `当前状态` 只允许六种：`观察中` / `提请恢复` / `建议永久删除` / `已恢复` / `已删除` / `档位待定·上游劣化`。
  - 前五种是摘出源的正式状态。
  - `档位待定·上游劣化` 用于**仍在成品中、但档位暂时测不出来**的源：上游三端点大面积超时，均值凑不齐，名称档位留空，同时在池里留痕并写下次复测日期，避免长期无档位、无记录。上游恢复后补测并补档，随后从池中改「已恢复」。
- `用户裁决` 留空表示待裁决。

### 6.3 判定规则（写死）

1. 从成品摘出前**必须先备份完整原文**到 `备份\`，再改成品；未备份不得摘出。
2. 摘出即入池，状态「观察中」，下次测试必然复测。
3. 连续 3 次复测全通 → 改「提请恢复」，在 MD 中单列，等用户点头才放回成品。
4. 连续 3 次全挂 → 改「建议永久删除」，同样等用户点头。
5. 时通时不通永远保持「观察中」，不得因嫌烦删除。
6. 每次复测更新「最近测试时段」「累计轮次」，历史追加到 MD 变更记录，不复写。

### 6.4 MD 结构

- 顶部统计：观察中 N / 提请恢复 N / 建议永久删除 N。
- 每源一段：名称、首次发现、历次时段与结果、失败层、当前建议、待用户决定事项。
- 末尾变更记录：谁在哪天改了状态。

## 8. 坑位库

### 8.1 布尔 `false` 被 `safeJsonInt` 吞掉

- 现象：写 `"searchable": false` 后站点仍参与搜索。
- 根因：客户端按整数解析，布尔被吞后回落到默认可搜索。
- 正确做法：一律写数字 `0` 或 `1`，写完逐条核对最终值。
- 证据来源：TVBox `safeJsonInt` 实现与实机行为。

### 8.2 `;md5;` 后接的是客户端语法，不是真实 URL

- 现象：直接 GET 带 `;md5;` 的地址返回 404，误判源失效。
- 根因：该后缀由客户端解析校验，不是 HTTP 资源名。
- 正确做法：探活时截断 `;md5;` 之后再请求，或只校验 jar 文件本体。
- 证据来源：TVBox `JarLoader` 解析逻辑。

### 8.3 中文目录写成百分号编码 + `./` 相对路径

- 现象：线路配置取不到，站点全空。
- 根因：`clan://` 协议不认 URL 编码与相对路径。
- 正确做法：写 `clan://localhost/<包名>/<中文目录>/api.json`。
- 证据来源：TVBox 本地包加载失败记录。

### 8.4 jsDelivr 对 `.jar` 返回 403

- 现象：jsDelivr 地址下 jar 加载失败。
- 根因：CDN 拒绝二进制大文件。
- 正确做法：jsDelivr 只下发 JSON，jar 走 GitHub raw。
- 证据来源：实机加载日志。

### 8.5 raw 有 CDN 缓存

- 现象：推送 `main` 后仍返回上一版。
- 根因：raw.githubusercontent 缓存未刷新。
- 正确做法：用 tag 路径验证，tag 立即可见；或加随机查询参数。
- 证据来源：发布后在线校验记录。

### 8.6 包装层会引入回归

- 现象：包装版无分类，直连版正常。
- 根因：`type:3` + JS 包装的导入/解析错误被算到站点头上。
- 正确做法：同一站点包装版与直连版分别跑 `home`/`category` 对照，再定性。
- 证据来源：TVBox 21 条包装源事故。

### 8.7 接口 200 不等于可用

- 现象：`ac=list` 返回 200，但 `class` 为空。
- 根因：空壳接口用 200 掩盖无数据。
- 正确做法：分类非空、分类下有片、详情可解析、播放可拉流，逐级验到真拿到东西。
- 证据来源：小猫影视 v1.2.0 假可用。

### 8.8 `extra.category` 只认数组未验证

- 现象：写入 JSON 字符串数组后不确定客户端是否渲染。
- 根因：官方文档对 maccms 该字段的语义描述为「分类 ID 或名称」，与数组用法存在歧义。
- 正确做法：优先不依赖该字段；确需使用时先真机验证，再全量写入。
- 证据来源：`参考资料/小猫影视/docs/create_source.md`。

### 8.9 直播 m3u8 要验首行

- 现象：HTTP 200 但播放器无频道。
- 根因：返回的是 HTML 错误页或登录页。
- 正确做法：读前 8 KB，首行必须 `#EXTM3U`。
- 证据来源：直播探活记录。

### 8.10 四段全过也可能播放卡

- 现象：分类、详情、地址全通，实际播放卡顿。
- 根因：源站 CDN 吞吐只有码率的 0.4–0.8 倍，属源站限速。
- 正确做法：单列「卡」档，按实测速率/码率比值判档；不得计入「流畅可用」，不与流畅源混排；源侧不可修复的写明。
- 证据来源：小猫影视 1.3.0，360/猫眼/非凡实测 434–1081 kbps、码率 800–2525 kbps；ikun 实测 3810 kbps、码率 4824 kbps，同样未达流畅线。

### 8.11 移除 `extra.category` 后成人分类不再置后

- 现象：上游成人分类按原顺序出现，无 `（成人）` 后缀。
- 根因：置后与后缀依赖 `extra.category`，不依赖该字段就失去重排能力。
- 正确做法：在规范与发布说明写明该代价；曝光控制只靠「成人主体源进非公开台账」，公开源内夹带分类按上游原样展示；待真机验证字段后再恢复置后。
- 证据来源：小猫影视 1.3.0 配置变更。

### 8.12 分类为空被误判为失效

- 现象：首页/分类取不到内容，源被记为失败并摘出。
- 根因：只跑分类路径，未补测搜索；部分源只开放搜索接口。
- 正确做法：按 3.5 补测固定关键词搜索路径；分类为空但搜索能出结果、详情与播放/正文可取的，记「仅搜索型」收录，不判失败。
- 证据来源：2026-11-08 用户反馈「源测试运行没有结果，是不是源只能搜索」。
