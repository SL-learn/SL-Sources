# 小猫影视源规范

> 位置：`规范/小猫影视源规范.md`｜地位：小猫影视（catmovie）应用的全部强制条款正本。

本规范用于约束「小猫影视」（catmovie）自建点播源与直播源的制作、构建、分发、探活、门禁与维护，使不同批次、不同制作人产出的源在字段、命名、目录、发布方式和验收口径上保持一致。本规范不照抄 TVBox 规格：小猫影视没有 jar/py 插件、没有本地包、没有顶层 `parses`/`spider`，对应能力按小猫自身机制重新定义。

## 1 定位与范围

**CAT-PRC-001【硬约束】** 本规范只覆盖小猫影视的两类点播源（`type=0` maccms、`type=1` JS/universal）与一类直播源（`lives[]`）。不接受 TVBox 的 jar/js/py 站点定义直接搬入，也不接受 TVBox 顶层 `parses`/`spider`/`sites[].ext` 结构。

**CAT-PRC-002【硬约束】** 规范适用客户端版本为 `>=2.6.0`。依据 A：`docs/create_source.md:4` 明示「该文档仅适用于 >=2.6.0 版本」；本轮实测最新发布为 `release-v2.6.1`（2025-11-07）。2.5.9 及更早版本不在本规范覆盖范围。

**CAT-PRC-003【规范约定】** 本轮交付边界为：研究结论、机制说明、规范文档、示例骨架。不生成完整成品源包，不推送远程仓库，不修改 `tvboxSL\` 下任何 TVBox 目录，不修改仓库根 `README`。

**CAT-PRC-004【规范约定】** 小猫影视不要求电视端适配（官方明确不支持 TV，依据 A：`intro/qa` 与 issue #145），因此命名长度、封面比例等约束按手机竖屏与桌面窗口的实际展示来定，不沿用 TVBox 的电视端规则。

**CAT-PRC-005【规范约定】** 术语：源（一条 `Iconfig` 或一条 `ILiveItem`）；线路（同一点播站点的不同入口，或详情内的不同播放列表）；订阅（客户端「视频源管理」中添加的一个配置文件 URL）；发布物（一次发布提交给用户的 JSON 文件集合）。

## 2 客户端事实基线

### 2.1 加载机制

**CAT-CFG-001【硬约束】** 小猫影视是空壳客户端，不带内置源；源必须由用户通过「视频源管理」添加配置 URL 后生效。依据 A：`intro/qa`「下载之后打开啥都没有啊」。任何要求「安装即自带源」的方案不成立。

**CAT-CFG-002【规范约定】** 配置加载路径为：

1. 用户添加配置 URL（或点击 `xm://sub?url=<配置URL>` 订阅链接）。
2. 客户端拉取该 URL 返回的 JSON，按顶层形态解析为源集合（数组或三键对象）。
3. 源集合进入源管理列表；点播源按 `type` 分流：`0` 走 maccms 原生适配，`1` 走 JS 引擎执行 `extra.js` 中的函数体。
4. 播放时，`videos[].url` 为直链则直接播放；`videos[].id` 为 iframe 则先走 `parseIframe`，失败后回退无头浏览器嗅探。

依据 A：`docs/create_source.md:102-114`、`178-242`、`426-440`；B：`index.d.ts:793-858`、`1029-1065`。

**CAT-CFG-003【规范约定】** JS 源运行在 Flutter JS 引擎中（A：`docs/create_source.md:253`；E：PR #147「add universal adapter」已于 2025-09-18 合入 `dev`）。该环境只提供文档列出的 polyfill，不是完整浏览器；`XMLHttpRequest` 与 `localStorage` 是内存模拟，不会真实发起请求或持久化（A：`docs/create_source.md:270-277`、`302-307`）。

**CAT-CFG-004【规范约定】** 客户端默认缓存 HTTP 请求结果；同一 URL 在参数不同时也会命中同一缓存，需要显式 `noCache: true` 才绕过。依据 B：`index.d.ts:225-238`；E：PR #171「Fix: dio cache」已于 2025-09-27 合入 `dev`。

**CAT-CFG-005【规范约定】** 客户端提供 `xm://reset` 缓存重置入口（A：`docs/protocol.md:5-6`，说明为「清除缓存（重置）」）。该入口是本规范唯一可承诺的「强制刷新」手段，发布变更后的用户侧兜底动作。

**CAT-CFG-006【规范约定】** 敏感源由源级 `nsfw` 字段标记，客户端默认不显示；需要在设置中开启「绅士模式」后才显示。开启路径有三种：搜索框输入 `114514` 回车（只显示设置项）、设置中连点版本号 10 次（直接开启）、打开深链 `xm://nsfw?enable=1`。依据 A：`intro/qa`、`docs/protocol.md:7-8`。该机制只影响显示，不提供分类级屏蔽。

**CAT-CFG-007【待验证】** 源管理列表是否已具备分组、排序、批量启停能力。已知 issue #21 曾提出该诉求且已关闭，但关闭不等于已实现。验证方法：2.6.1 真机添加含 20 条源的配置，观察列表是否有分组标题、排序入口、批量开关；结果写入发布记录。在验证前，所有分组信息只能编码进 `name`（见 CAT-NAM-010）。

### 2.2 与 TVBox 的关键差异

| 维度 | TVBox | 小猫影视 | 对自建源的影响 |
|------|--------|----------|----------------|
| 客户端形态 | 开源，站点适配器可扩展 | 2.5.9 后闭源，仅 maccms 原生 + JS 引擎 | 不能给客户端源码行号；能力边界靠官方文档与实测 |
| 配置顶层 | `sites`/`lives`/`parses`/`spider` 等多键 | 数组，或 `{sites,data,lives}` | 无 `parses`/`spider` 可写 |
| 站点类型 | `type` + `api` 判定 jar/js/py/ts 等 | 只有 `type=0`（maccms）与 `type=1`（JS） | TVBox 的 jar/py/php 源必须重写 |
| 爬虫载体 | 独立文件（jar/js/py）+ md5 校验 | 代码内联为字符串，存在配置 JSON 的 `extra.js` | 无独立文件、无文件级 md5、无法运行时 `import` |
| 播放解析 | 顶层 `parses` 多解析器 + flag | `extra.jiexiUrl` 单接口 + `parseIframe` + 嗅探 | 无多解析器优先级体系 |
| 直播 | `lives` 带分组/EPG/多类型 | `lives[]` 只有 `name/url/type(0 m3u,1 txt)` | 无 EPG 字段，分组只能写进 `name` |
| 分类控制 | `categories` 分类白名单（运行时过滤） | maccms 用 `extra.category`；JS 用 `getCategory` 返回值 | 无运行时分类级屏蔽开关 |
| 敏感源 | `searchable`/`changeable` 等逐源开关 | 源级 `nsfw` + 全局绅士模式 | 只能整源标记，不能逐分类 |
| 本地包 | 目录包 + 相对路径 + file:// | 只接受 URL（无本地包概念） | 本地分发需自建 HTTP 服务（见 CAT-DIST-001、CAT-DIST-002） |
| 缓存/版本 | jar md5 + 3 天缓存 | URL 级 HTTP 缓存；无配置 md5 字段 | 版本控制靠 URL 版本化与 JS 内版本门控 |
| 平台 | 电视横屏为主 | 手机/桌面；官方不支持 TV | 名称长度、封面比例、交互路径不同 |

**CAT-CFG-008【规范约定】** 跨客户端复用只允许复用「上游 maccms 接口」这一层，禁止复用 TVBox 的适配器代码与配置片段。转换与冲突规则见 CAT-STR-022、CAT-STR-023。

**CAT-CFG-009【硬约束】** 小猫没有「相对路径」语义：`type=0` 的 `api` 必须是绝对 URL；`type=1` 的 `api` 只作为 `env.baseUrl` 字符串，任何相对路径拼接由 JS 代码自行完成。禁止写 `./config.json`、`../sources/x.json`、`file://` 之类引用。

## 3 目录与命名

### 3.1 建议目录结构（本轮只写不建）

**CAT-NAM-001【规范约定】** 仓库采用「按应用分层」，小猫影视作为独立应用放在 `apps/catmovie/`，与 TVBox 的 `tvboxSL/` 平级、互不引用。建议结构：

```
apps/
  catmovie/
    sources/                 # 源工程，不进发布物
      ts/                    # 每个源一个 .ts（必须放在子目录，见 CAT-STR-025）
      scripts/               # 组装、探活、门禁脚本
      package.json
    dist/                    # 发布物快照，按版本目录
      v1.0.0/config.json     # 单文件全量：sites + data + lives 同一个文件
      stable/config.json     # 稳定入口（复制或重定向均可，需可匿名直链访问）
    records/                 # 探活与门禁留证
      probe/
      gate/
```

**CAT-NAM-002【规范约定】** 发布物目录与文件名只使用 ASCII：`[a-z0-9._-]`，禁止中文、空格、大写混排。原因：配置 URL 会进入客户端网络层与订阅链接，中文与空格在部分平台会被二次编码导致 404。

**CAT-NAM-003【规范约定】** 每次发布必须同时落盘 `records/probe/<版本>-probe.json` 与 `records/gate/<版本>-gate.json`；没有留证的发布视为未验证发布。

### 3.2 标识与名称

**CAT-NAM-004【硬约束】** `id` 由站点主域名规则化生成：取 `api` 的 host，转小写，非 `[a-z0-9]` 字符一律替换为 `_`。例：`caiji.dyttzyapi.com` → `caiji_dyttzyapi_com`；`bfzyapi.com` → `bfzyapi_com`。依据 D：60 条样本全部符合该规则（`jhysj_jiaheyy_top`、`www_lovedan_net` 等）。

**CAT-NAM-005【硬约束】** `id` 全局唯一且不得复用。源下线后保留该 `id` 到「已退役清单」，新源不得占用；同一站点需要第二条线路时用后缀 `_2`、`_3`，不得改动主 `id`。

**CAT-NAM-006【硬约束】** `id` 长度 3-48 字符，字符集 `[a-z0-9_]`，禁止以 `_` 结尾、禁止连续双下划线。依据：官方文档要求「唯一标识，不能重复」（A：`docs/create_source.md:72`）；字符集与长度为本规范约定。

**CAT-NAM-007【待验证】** 客户端对重复 `id` 的实际处理（忽略后者、覆盖前者、还是全部显示）。验证方法：构造含两条相同 `id` 的配置，真机导入后观察源列表条数与生效源。在验证前，CAT-NAM-005 按硬约束执行以规避风险。

**CAT-NAM-008【规范约定】** 点播源 `name` 采用 `速度档位｜站点中文名`（全角竖线），档位枚举见 CAT-PRB-012；站点名部分 ≤10 个汉字；不带方括号、不带域名。依据 D：60 条原始样本 `name` 中位数为 4 个汉字；档位前缀为本规范新增约定，用于弥补小猫无源分组能力（CAT-CFG-007）。

**CAT-NAM-009【规范约定】** 同站点的备线名称用 `·备线`、`·备2` 后缀，例如 `百度资源·备线`；禁止用 `(1)`、`-2`、`副本` 之类无意义后缀。

**CAT-NAM-010【规范约定】** 直播源 `name` 使用 `分组｜名称` 全角竖线格式，分组取固定枚举：`央视`、`卫视`、`地方`、`影视轮播`、`体育`、`综合`。依据 D：7 条直播样本全部为该格式（`央视｜咪视界`、`卫视｜央视卫视`、`综合｜VBSKY综合`、`影视轮播｜YY轮播`、`体育｜咪咕睛彩赛事`）。

**CAT-NAM-011【硬约束】** `name` 不得出现敏感词、成人向暗示、引战词；不得出现「破解」「VIP免费」等承诺性表述。判定按 CAT-SEC-001 词表执行。

**CAT-NAM-012【规范约定】** 跨客户端同名源（同一上游同时存在于 TVBox 与小猫）保持同一中文名，靠 `id` 区分；若两个不同上游同名，小猫侧加域名括号后缀，例如 `百度资源（apibdzy）`。

## 4 配置格式

### 4.1 顶层形态

**CAT-CFG-010【硬约束】** 配置文件顶层只允许两种形态：

1. 纯数组：`[ {源1}, {源2} ]`，只含点播源。
2. 对象：`{ "sites": [点播源], "data": [点播源], "lives": [直播源] }`，三个键均可省略，但至少要有一个非空键。

依据 A：`docs/create_source.md:15-64`；D：点播样本为纯数组，直播样本为 `{"lives":[...]}`。

**CAT-CFG-011【待验证】** `data` 键与 `sites` 键在客户端中的实际差异（是否进入同一列表、是否参与搜索、是否单独分组）。验证方法：构造 `{"sites":[A],"data":[B],"lives":[]}`，真机导入后分别检查源列表、搜索范围、首页展示。验证前，本规范默认把全部点播源写入 `sites`，`data` 保持空数组。

**CAT-CFG-012【硬约束】** 文件必须是标准 JSON：UTF-8 无 BOM，无注释、无尾逗号、无单引号。官方文档示例使用 `jsonc` 注释仅为说明用途（A：`docs/create_source.md:15`），发布物不得带注释。依据：Dart `jsonDecode` 不接受注释与尾逗号，该点为工程常识，按硬约束执行以规避风险。

**CAT-CFG-013【待验证】** 客户端是否容忍带注释的配置文件。验证方法：用带 `//` 注释的同一配置导入，观察是否报错。即使验证为「容忍」，发布物仍按 CAT-CFG-012 执行。

### 4.2 点播源字段

| 字段 | 类型 | 必填 | 默认 | 本规范要求 | 依据 |
|------|------|------|------|------------|------|
| `id` | string | 是 | — | 按 CAT-NAM-004 生成，唯一 | A:72；D:60/60 |
| `name` | string | 是 | — | 按 CAT-NAM-008/CAT-NAM-009/CAT-NAM-011 | A:73；D:60/60 |
| `type` | int | 是 | 0 | 只允许 `0` 或 `1` | A:74；B:815；D:60/60 全为 0 |
| `api` | string | 是 | — | 见 CAT-CFG-014 | A:75；B:817-829 |
| `nsfw` | bool | 是 | false | 布尔字面量，判定见 CAT-SEC-001 | A:78；B:831-836；D:60/60（15 条为 true） |
| `logo` | string | 否 | `""` | 保留空串；有官方 logo 时用 https | A:76；D:60/60 为空串 |
| `desc` | string | 否 | `""` | 可省略或空串；不得写营销语 | A:77；D:0/60 |
| `status` | bool | 否 | true | 不写入；下线靠删除源实现 | A:79；D:0/60；【待验证】见 CAT-CFG-015 |
| `extra` | object | 否 | — | 只允许下方 extra 表中的键 | A:81-91；B:716-781 |

**CAT-CFG-014【硬约束】** `api` 必须是完整可请求 URL，且不得携带 `?`/`&` 查询串。

- `type=0`：统一使用 `https://<host>/api.php/provide/vod/`（保留末尾斜杠），XML 上游用 `https://<host>/api.php/provide/vod/at/xml`。依据 D：60 条样本中 59 条为带末尾斜杠的标准路径，1 条为自定义文件名 `https://api.xinlangapi.com/xinlangapi.php/provide/vod`；B:817-827 的类型示例同样带末尾斜杠。
- `api` 的形态不以字符串是否标准判定，以「`api` 与 `?ac=list` 正确拼接后能返回 maccms 结构」为准；拼接时禁止在 `api` 与 `?` 之间额外插入 `/`。官方文档中的 `https://cj.apibdzy.com/inc/api.php` 属于历史示例，不得据此放宽探活。
- 上游不支持 `https` 时允许降级为 `http://`，但必须同时满足：`https` 实测不可用（证书校验失败、无 443 监听或连接被拒）、`http` 探活三端点通过、降级原因写入探活记录并在验收报告逐条列明。E：`cj.lziapi.com` 的 `https` 证书校验失败（curl 错误 60）、`jhysj.jiaheyy.top` 无 `https` 响应，两者 `http` 三端点均正常。
- `type=1`：`api` 是站点根 URL（如 `https://example.com`），不带路径与参数；JS 代码通过 `env.baseUrl` 读取它。依据 B:817-827。

**CAT-CFG-015【待验证】** `status` 是否被客户端读取并影响可用性。验证方法：构造 `status:false` 的源，观察源列表中是否出现、能否请求。验证前不写入该字段。

**CAT-CFG-016【硬约束】** 禁止自造顶层字段（如 `enable`、`group`、`tags`、`weight`）。客户端只按已知字段解析，未知字段是否保留无证据，写入只会造成「看起来生效、实际无效」的混合态。依据 B：`Iconfig` 只有 8 个字段。

### 4.3 maccms 上游接口契约（type=0）

小猫的 `type=0` 由客户端原生适配，本规范不重写适配器，但接入与探活必须按下列上游契约判定。

| 动作 | 请求 | 关键返回字段 | 依据 |
|------|------|--------------|------|
| 分类与首页 | `?ac=list` | `class[].type_id/type_name`、`list[]`、`pagecount`、`total` | E：本轮 5 条源实测 |
| 分类分页 | `?ac=videolist&t=<type_id>&pg=<n>` 或 `?ac=detail&t=<type_id>&pg=<n>` | `list[]`、`pagecount`、`total` | D：示例源 `vod_utils.ts` 用该组参数探测分类 |
| 详情 | `?ac=detail&ids=<vod_id>` | `list[0].vod_name/vod_pic/vod_remarks/vod_content`、`vod_play_from`、`vod_play_url` | E：实测 `detail` 与 `videolist` 两种 `ac` 均返回详情 |
| 搜索 | `?ac=detail&wd=<关键词>&pg=<n>` | `list[]` | E：实测可用 |
| XML 形态 | `.../provide/vod/at/xml` | `<rss><list pagecount total><video><dd flag="线路">` | E：实测 `cj.ffzyapi.com` XML 变体可解析 |

播放字段结构：`vod_play_from` 用 `$$$` 分隔线路名；`vod_play_url` 用 `$$$` 分隔线路，每线内用 `#` 分隔集，每集为 `集名$地址`。

**CAT-CFG-017【硬约束】** 接入与探活必须请求 `ac=list` 并解析 `class`/`list`/`pagecount`，不得用站点首页 HTML 作为可用性证据。

**CAT-CFG-018【规范约定】** 详情解析必须同时兼容 JSON 与 XML；`vod_play_from` 与 `vod_play_url` 的 `$$$` 分段数必须一致，不一致的源判「间歇」并要求上游核对。

**CAT-CFG-019【规范约定】** 上游字段值为 `null` 时按空串降级处理，禁止把字符串 `"null"` 写入播放地址或封面。

**CAT-CFG-020【待验证】** 客户端实际使用的 `ac` 参数组合（`videolist` 还是 `detail`）与分页上限。验证方法见 V8：用自建 mock maccms 记录真实请求。

### 4.5 字段真伪判定

下表用「官方文档 + 官方类型 + 真实样本」三方交叉核对，回答哪些字段真被读取、哪些只是写进去没人用。样本口径：点播 60 条、直播 7 条。

| 字段 | 官方文档 | 类型定义 | 样本使用 | 判定 |
|------|----------|----------|----------|------|
| `id` | 必填 | `Iconfig.id` | 60/60 | 确认读取，且用于唯一标识 |
| `name` | 必填 | `Iconfig.name` | 60/60 | 确认读取 |
| `type` | 必填 | `0 \| 1` | 60/60 全为 0 | 确认读取，决定适配器分流 |
| `api` | 必填 | `Iconfig.api` | 60/60 | 确认读取 |
| `nsfw` | 选填，默认 false | 必填 boolean | 60/60（15 条 true） | 确认读取（绅士模式据此隐藏） |
| `logo` | 选填，默认空串 | `logo?: string` | 60/60 为空串 | 类型支持，样本未提供非空值，是否真实渲染无证据；按可选保留 |
| `desc` | 选填，默认空串 | `desc?: string` | 0/60 | 类型支持，样本未使用；按可选保留，不依赖 |
| `status` | 选填，默认 true | 无此字段 | 0/60 | 文档声明但类型未定义，按「未读取」处理（V3） |
| `extra` | 选填 | `extra?: IconfigExtra` | 0/60 | 类型与文档均声明读取；样本未使用，靠 d1y 示例源与官方注释佐证 |
| `extra.gfw` | 选填 | `gfw?: boolean` | d1y 示例有 | 是否影响请求路由未证实，按「显示标记」保守使用（CAT-CFG-022） |
| `extra.template` | 选填 | `"t4"` | 未见真实源 | 官方注释承认 t4 嗅探有问题，禁用（CAT-CFG-026） |
| 自造键 | 无 | `[prop: string]: any` | 无 | 类型允许但无消费证据，禁止写入（CAT-CFG-016） |

**CAT-CFG-027【规范约定】** 判定原则：官方文档、类型定义、真实样本三者同时具备才可认定为「确认读取」；只有文档或只有类型声明的字段，只能按可选字段保守写入，不得依赖其行为；三者都没有的一律禁止。

**CAT-CFG-028【硬约束】** `status` 不得出现在发布物中；需要下线源时直接删除该条目，并通过 `records/retired-ids.txt` 保留 `id`（CAT-PRC-020）。

## 5 JS 源契约（type=1）

### 5.1 方法与返回值

| 方法 | 配置键 | 必选 | 入参来源 | 返回值 | 依据 |
|------|--------|------|----------|--------|------|
| `getConfig` | 无（构建期抽取） | 是 | — | `Iconfig` | B:877 |
| `getCategory` | `extra.js.category` | 是 | — | `ICategory[]` | B:907 |
| `getHome` | `extra.js.home` | 是 | `page`/`category`/`limit` | `IMovie[]` 或 `IHomeData` | B:924 |
| `getDetail` | `extra.js.detail` | 否 | `movieId` | `IMovie` | B:940 |
| `getSearch` | `extra.js.search` | 否 | `keyword`/`page` | `IMovie[]` | B:957 |
| `parseIframe` | `extra.js.parseIframe` | 否 | `iframe` | `string` 或 `string[]` | B:981 |

**CAT-STR-001【硬约束】** `type=1` 的源必须同时提供 `category` 与 `home`；缺 `home` 会导致首页空白，缺 `category` 会导致分类区为空。依据 A：`docs/create_source.md:240-369`；B:477-558。

**CAT-STR-002【硬约束】** 配置中 `js.*` 的值是函数体代码字符串，不是方法名。禁止写成 `"home": "getHome"`。依据 C：`JS/cli/parse.js:193-203`（工具输出的是去掉外层花括号的函数体）；A：`docs/create_source.md:389-416` 中的方法名写法属于文档占位，不得照抄。

**CAT-STR-003【硬约束】** 函数体允许顶层 `return` 与 `await`（客户端以异步函数包裹执行）。依据 D：d1y 示例源与样本均按该写法生成并通过客户端使用。

**CAT-STR-004【硬约束】** 函数体内只能引用客户端注入的全局对象与语言内置对象：`kitty`、`env`、`req`、`dayjs`、`btoa`/`atob`、`URL`/`URLSearchParams`、`TextEncoder`/`TextDecoder`、标准 `JSON`/`Math`/`Date` 等。禁止引用任何外部模块符号（包括同仓库 `utils.ts` 导出的函数），因为构建产物只保留函数体，被引用的符号在运行时不复存在。依据 A：`docs/create_source.md:251-311`；C：`parse.js:193-203`。

**CAT-STR-005【硬约束】** 禁止使用 `fs`、`path`、`process`、`Buffer`、`require`、`import`、`child_process` 等 Node 能力。客户端 JS 引擎不提供这些对象。依据 A：polyfill 清单（`docs/create_source.md:255-277`）。

**CAT-STR-006【硬约束】** 禁止用 `XMLHttpRequest`、`localStorage`、`sessionStorage` 完成业务逻辑：前者是模拟实现不会真实发请求，后者只存在于内存。网络一律用 `req`。依据 A：`docs/create_source.md:270-277`、`304-311`。

**CAT-STR-007【规范约定】** `env` 参数语义：

| 键 | 含义 | 取值 | 使用要求 |
|----|------|------|----------|
| `baseUrl` | 源配置的 `api` | string | 必须用它拼请求，禁止硬编码域名 |
| `category` | 分类 ID | string | 首屏可能为空串，必须处理「全部」分支 |
| `page` | 页码 | int | 从 1 开始，缺省按 1 |
| `limit` | 每页条数 | int | 用于分页大小，缺省按 20 |
| `movieId` | 详情 ID | string | 只在 `detail` 中使用 |
| `keyword` | 搜索词 | string | 只在 `search` 中使用，必须 `encodeURIComponent` |
| `iframe` | iframe 地址 | string | 只在 `parseIframe` 中使用 |

依据 B:55-91；D：d1y 示例源用法一致。

**CAT-STR-008【硬约束】** 任何「URL 相同、参数不同」的请求必须显式 `noCache: true`，否则第二次会拿到第一次的缓存。典型场景：同一 `/api` 用不同 POST body、同一播放页用不同 query 取不同集。依据 B:225-238；E：PR #171。

**CAT-STR-009【硬约束】** 返回结构必须严格符合类型：

- `ICategory[]`：`{ text, id }`，两者均为 string，`id` 不得为数字。
- `IMovie`：`{ id, title, cover, remark?, desc?, playlist? }`，前三项必填。
- `IPlaylist`：`{ title, videos }`，`videos` 非空。
- `IPlaylistVideo`：`{ text, url? , id? }`，`url` 与 `id` 必须二选一且只能有一个。
- `IHomeData`：`{ type: 'list' | 'complex', data }`；`complex` 不支持分页。

依据 B:301-398、458-471。

**CAT-STR-010【硬约束】** 详情必须返回 `playlist`，且每个线路至少 1 个可播放项；若只能给 iframe，必须提供 `parseIframe` 或配置 `sniffer`，否则该集不可播。依据 A：`docs/create_source.md:426-440`；B:1045-1064。

**CAT-STR-011【规范约定】** `parseIframe` 返回数组时客户端只取第 `[0]` 项（B:962），因此多清晰度场景不要靠数组表达，改为拆成多条 `playlist` 线路。

**CAT-STR-012【规范约定】** `getHome` 用于「分类 + 分页」列表；不得把 `getHome` 写成只返回固定首页推荐而忽略 `category`/`page`，否则分类翻页失效。

**CAT-STR-013【规范约定】** 单方法的网络请求不超过 3 次，单次超时按 10 秒设计；需要多次请求时先取最小必要数据，禁止在 `getHome` 里对每个条目再发一次详情请求（N+1）。该条为性能约定，依据为客户端无批量并发控制与移动端网络环境。

**CAT-STR-014【规范约定】** 版本门控写法：

```js
if (!(await kitty.version_compare(kitty.VERSION, '2.6.0'))) return []
```

`version_compare(old, _new)` 语义为「old >= new」，依据 B:156-159 与 D：d1y `utils.ts` 的实现。客户端参数顺序是否与此一致标【待验证】，验证方法：在 2.6.0/2.6.1 分别调用 `version_compare(kitty.VERSION,'2.6.0')` 与 `version_compare('2.6.0', kitten.VERSION)` 打印结果对比。

### 5.2 嗅探与解析优先级

**CAT-STR-015【规范约定】** 播放地址解析优先级固定为：`videos[].url` 直链 > `parseIframe` 返回 > 无头浏览器嗅探。依据 B:740-755（「parseIframe 优先级高于无头浏览器嗅探」）。

**CAT-STR-016【规范约定】** 启用嗅探时，`customRegex` 必须限定到媒体后缀（`https?://.*\.(m3u8|mp4)(\?|$)`），`exclude` 必须排除统计与广告域；禁止留空依赖默认规则。依据 B:600-633。

## 6 多线路与索引

**CAT-STR-017【规范约定】** 源级多线路：同一上游有多个入口（主域名/备用域名/不同 CDN）时，每条入口一个源条目，`id` 用 `_2`、`_3` 后缀，`name` 用 `·备线` 后缀；禁止把多个入口塞进同一个 `api` 的逗号分隔串。

**CAT-STR-018【规范约定】** 详情内多线路：`playlist[].title` 使用 `线路1`、`线路2` 或上游原始线路名（如 `ffm3u8`）；禁止使用「高清」「超清」做线路名，清晰度写入 `videos[].text`。

**CAT-STR-019【规范约定】** 分类白名单：maccms 源若上游存在空分类或成人分类，用 `extra.category` 显式列出保留分类；JS 源在 `getCategory` 返回值中直接剔除。禁止在 `getHome` 里靠 `if` 过滤成人分类来「补救」，因为分类列表仍会暴露。

**CAT-STR-020【规范约定】** 单文件全量发布：一个配置文件同时承载全部点播源（`sites`）与直播源（`lives`），用户只添加一个订阅 URL。客户端不支持「订阅嵌套订阅」，禁止设计 `index.json` 让客户端二次拉取；需要按站点回滚时用版本目录，不拆订阅。

**CAT-STR-021【规范约定】** 允许在仓库内维护 `index.json` 作为「人读的线路清单」（含线路名、URL、源数、探活结论）；该文件仅供发布流程与用户手动添加使用，客户端不读取，禁止在文档中把它描述为「客户端索引」。

**CAT-STR-022【硬约束】** 与 TVBox 源的复用边界：

- 可复用：maccms 上游接口（同一 `api` 可同时供 TVBox 与小猫使用）。
- 不可复用：TVBox 的 `jar`/`js`/`py`/`php` 适配器、`spider` 字段、`ext` 站点扩展、`parses` 解析器定义。
- 转换：TVBox `sites[].key` → 小猫 `id`（按 CAT-NAM-004 重算，不沿用 key）；`sites[].name` → `name`（同名冲突按 CAT-NAM-012）；`sites[].api` → `api`（仅限 maccms 形态）。

依据 E：本轮比对 `参考资料/TVBox-wuxierj/星微261018，本地包/tvboxTW` 全部 `api.json`，maccms 主机仅 10 个；与小猫 60 条样本重合 6 个（`360zy.com`、`api.niuniuzy.me`、`api.wsyzy.net`、`caiji.dyttzyapi.com`、`caiji.moduapi.cc`、`cj.lziapi.com`）。

**CAT-STR-023【硬约束】** 转换后不得沿用 TVBox 的 `key` 作为 `id`（TVBox key 常为 4 位任意串，既不符合 CAT-NAM-004，也可能与已有源碰撞）。名称冲突处理：保留小猫侧主名，TVBox 侧只改 `key` 不改 `name`。

**CAT-STR-024【待验证】** 同一条配置被用户重复添加两次时客户端的行为（去重、叠加、还是报错）。验证方法：同一 URL 添加两次后观察列表。验证前，发布流程保证同一线路只提供一个 URL。

## 7 源工程、资源与公共库复用

### 7.1 工程约束

**CAT-STR-025【硬约束】** TS 源文件必须放在子目录（如 `sources/ts/`）。官方 CLI 扫描时跳过根目录下的 `.ts`，只收集子目录中的文件。依据 C：`JS/cli/parse.js:244-264`（条件 `item.endsWith('.ts') && !one`）。

**CAT-STR-026【硬约束】** `getConfig` 的返回值只允许字面量：字符串、数字、布尔。使用变量或常量标识符会被工具跳过并只打印警告。依据 C：`parse.js:83-93`、`107-110`。因此 `api`、`id`、`name` 必须直接写字面量，禁止 `const API = ...; return { api: API }`。

**CAT-STR-027【硬约束】** 工具不会抽取 `extra` 里的嵌套对象。`extra.js` 与 `extra.sniffer` 若写在 `getConfig` 内会被丢弃。依据 C：`parse.js:94-116`（只处理 String/Numeric/Boolean 字面量）。正确做法二选一：

1. `getConfig` 只返回 `id/name/type/api/nsfw`，`js` 由工具自动写入，`sniffer` 由发布脚本合并。
2. `getConfig` 内不写 `extra`，构建后用组装脚本统一补齐 `sniffer`/`searchLimit`/`category`。

**CAT-STR-028【硬约束】** 工具输出是纯数组（`JSON.stringify(allConfigs)`），不含 `sites`/`lives` 外壳。依据 C：`parse.js:314-317`。需要对象形态时由组装脚本二次包装，禁止手工改工具产物后当作「工具生成」交付。

**CAT-STR-029【规范约定】** 公共逻辑复用方式：由于函数体是独立字符串、运行时各自独立的作用域，公共逻辑必须在每个函数体内联（或由构建脚本把 helper 文本拼进每个函数体）。禁止建立「运行期共享库」假设。本规范推荐在 `sources/scripts/` 维护 helper 片段，构建时注入。

**CAT-STR-030【规范约定】** 构建必须可复现：`package.json` 锁定 `kitty`/`kitty-parse` 版本（或固定 git commit），构建命令写入脚本文件，产物与源码同批次提交到 `apps/catmovie/`（本仓不设 `dist/` 子目录，见 SYS-STR-003）。

**CAT-STR-031【规范约定】** 源工程不得引入需要真实 DOM 或 Node 原生模块的第三方库；可用的第三方库仅限纯 JS 且在 polyfill 清单范围内（A：`docs/create_source.md:255-277`）。

### 7.2 资源复用

**CAT-STR-032【规范约定】** 封面、logo 只使用上游直链，不在本仓库中转存图片。上游封面 403 时降级为空串，不得指向第三方图床。

**CAT-STR-033【规范约定】** 解析接口、嗅探正则等跨源共用配置，统一维护在 `sources/scripts/` 的常量片段中，由构建注入；禁止在各源内散落复制不同版本的正则。

## 8 本地分发

**CAT-DIST-001【硬约束】** 小猫影视不存在「本地包」概念：源是配置 JSON 中的条目，客户端只接受 URL（http/https）或 `xm://sub` 订阅链接，不接受目录包、不接受相对路径。依据 A：`docs/create_source.md:102-114`；对照 CAT-CFG-001。

**CAT-DIST-002【规范约定】** 本地/离线分发的等效方案是「本地 HTTP 静态服务」：

- Windows 桌面：`python -m http.server 8096 --directory <发布目录>`，手机与电脑在同一局域网时用 `http://<电脑局域网IP>:8096/config.json`。
- Android：在手机侧用文件管理器自带的 HTTP 服务或 Termux 启动静态服务，端口同 8096。
- 端口 8096 为本规范专用，避开现有长期占用端口 8080/8081/8092/8093。

**CAT-DIST-003【待验证】** 客户端是否接受 `file:///...` 或裸路径（`/sdcard/x.json`、`D:\x.json`）。验证方法：在「视频源管理」分别输入 `file:///sdcard/test.json`、`/sdcard/test.json`、`D:\test.json`，记录报错文案与是否加载成功。验证前，本规范不承诺任何本地路径写法。

**CAT-DIST-004【规范约定】** 本地静态服务必须满足：`Content-Type: application/json; charset=utf-8`、无鉴权、无防盗链、GET 可直取、目录列表关闭。禁止用需要登录的网盘直链作为「本地分发」。

**CAT-DIST-005【规范约定】** 本地分发验收：断开外网、仅保留局域网，冷启动客户端后添加 URL，源列表可见、首页有内容、详情可播、搜索可用，四项全过才算通过。

**CAT-DIST-006【规范约定】** 本地分发不得改变发布物内容：同一份 `config.json` 既用于本地也用于在线分发，禁止为本地单独生成「去掉 nsfw」的变体。

## 9 在线分发

**CAT-DIST-007【规范约定】** 托管优先级：GitHub 仓库 raw 直链 > GitHub Pages > jsDelivr > 第三方静态托管。国内访问场景允许在文档中提供 `gh-proxy`/`ghfast` 加速镜像，但客户端中添加的主 URL 必须是原始直链，加速链接只作为用户备选。

**CAT-DIST-008【硬约束】** 配置 URL 不得包含中文、空格、百分号编码后的中文、`#`（片段标识）、查询参数。依据 CAT-NAM-002 与订阅链接解析需要。

**CAT-DIST-009【规范约定】** URL 加密只使用官方两种规则：

- 普通 URL：`b` + Base64(完整 URL)。
- GitHub 规则：`g<user>/<repo>#<branch>/<path>` 再 Base64 并加前缀 `b`；分支省略时默认 `main`，客户端转换为 `https://raw.githubusercontent.com/<user>/<repo>/<branch>/<path>`。

依据 A：`docs/create_source.md:116-176`。

**CAT-DIST-010【规范约定】** 加密串生成后必须反向解码校验一次，确认解码结果与原始 URL 完全一致；禁止手写 Base64。校验命令：

```powershell
$raw = 'https://raw.githubusercontent.com/<user>/<repo>/main/catmovie/v1.0.0/config.json'
$enc = 'b' + [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($raw))
$enc
[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($enc.Substring(1)))
```

**CAT-DIST-011【规范约定】** 直链必须可匿名访问：不允许 302 到登录页、不允许 Referer 白名单、不允许按 UA 拦截。发布后必须用「无 Cookie、默认 UA」的独立会话复验一次。

**CAT-DIST-012【规范约定】** 单文件全量发布，每次同时提供两份 URL（指向同一份 `config.json`）：

- 版本直链：`.../catmovie/v<版本>/config.json`（不可变，用于回滚与留证）。
- 稳定入口：`.../catmovie/stable/config.json`（可变，内容等于当前推荐版本）。

**CAT-DIST-013【待验证】** 客户端对配置 URL 的缓存时长与刷新条件（是否遵循 `Cache-Control`、是否有本地持久化副本、重启是否重拉）。验证方法：用本地 HTTP 服务记录每次请求的时间戳与请求头；改文件后分别在「不操作」「下拉刷新（若存在）」「杀进程重启」「`xm://reset`」四种条件下观察是否拉取新内容。验证结果决定「stable 入口是否可覆盖更新」。

**CAT-DIST-014【规范约定】** 发布后用户侧刷新路径固定为：删除该订阅重新添加 → 不行再 `xm://reset` → 再不行重启客户端。文档与用户说明必须按此顺序描述，禁止承诺「保存即生效」。

**CAT-DIST-015【规范约定】** 在线分发验收：直链 200、`Content-Type` 正确、UTF-8 无 BOM、单文件大小 ≤2 MB（超过时按站点裁剪，不拆订阅）、`jq`/`ConvertFrom-Json` 可解析、`id` 唯一、发布物 `nsfw=true` 计数为 0。

## 10 版本与校验

**CAT-VER-001【规范约定】** 版本号 `v<主>.<次>.<修订>`，语义：主=结构调整（字段/目录/线路拆分），次=源增删，修订=同一批源内的字段修正。版本号只写在发布目录与留证文件里，不写入 `Iconfig`（客户端不读该字段）。

**CAT-VER-002【硬约束】** 兼容声明只能写在 JS 函数体内，使用 `kitty.VERSION` + `kitty.version_compare` 做门控（CAT-STR-014）；禁止假设存在「配置级最低版本字段」。

**CAT-VER-003【硬约束】** 小猫影视没有配置级 md5/checksum 字段，禁止在配置中写 `md5`、`hash`、`version` 期望客户端校验。真实可用的校验手段只有两种：

1. 发布流程内校验：生成 `records/<版本>-checksums.txt`（每文件 md5），供人工与 CI 比对。
2. 运行时校验：JS 源可用 `kitty.md5(str)` 对上游响应做指纹判断（B:161-172），仅用于业务判断，不作为发布完整性校验。

**CAT-VER-004【规范约定】** 回滚：保留最近 3 个版本目录；发生故障时把 `stable/config.json` 恢复为上一版本内容，并在变更记录中注明回滚原因与时间。

**CAT-VER-005【规范约定】** 发布记录最少字段：版本号、发布日期、源数量（按 type 分组）、探活结论分布、门禁结论、变更摘要、发布人。

## 11 内容门禁

**CAT-SEC-001【硬约束】** 源级判定分「站点级」与「分类级」两级，两级都必须可证实、可留证：

1. 站点级（决定是否发布与 `nsfw` 取值）：满足任一即判 `nsfw=true`，按 CAT-SEC-002 不发布——成人分类数占分类总数 ≥30%；或抽样条目标题命中词表 ≥3 条；或站点自述、导航、公开标注显示以成人内容为主。
2. 分类级（决定是否可用）：含个别成人分类但不构成站点主题（成人分类 <30% 且标题抽样命中 <3 条）→ `nsfw=false`，但必须用 `extra.category` 白名单剔除命中分类（CAT-STR-019、CAT-SEC-003），发布视图内成人分类数必须为 0，且门禁记录同时留证「原始命中分类」与「剔除后保留分类」。

判据依据 D：60 条真实样本中 `360资源` 含 `伦理片` 分类却标注 `nsfw=false`，而 15 条成人站标注 `nsfw=true`；说明该字段的真实语义是「站点主题」而非「是否含成人分类」，单以任一分类名命中即判 nsfw=true 会与真实样本冲突，并使 CAT-SEC-003 的白名单路径失效。

词表基线（不区分大小写）：

```regex
(成人|福利|伦理|无码|有码|三级|情色|写真|里番|H动漫|18禁|adult|hentai|jav|nsfw|18\+)
```

**CAT-SEC-002【硬约束】** 发布物中 `nsfw=true` 的条目数必须为 0。成人源不进入公开发布配置；如需自用，另存于仓库外的私人目录，不进入公开发布物。

**CAT-SEC-003【规范约定】** 小猫没有 TVBox 那种「分类级运行时屏蔽」开关（B：`Iconfig`/`IconfigExtra` 无 categories 白名单字段）。可行替代路径只有两条：

- maccms：用 `extra.category` 只保留合规分类（CAT-STR-019），并在探活时确认被剔除分类确实无内容。
- JS：在 `getCategory` 返回值中不返回敏感分类，`getHome`/`getSearch` 对上游结果按分类 ID 二次过滤。

禁止假设客户端存在「敏感词过滤」或「开关级屏蔽」。

**CAT-SEC-004【硬约束】** `name`、`desc`、`logo` 一律中性：不出现敏感词、不出现功能承诺、不使用成人站惯用命名。直播分组名不得出现暗示性词汇。

**CAT-SEC-005【硬约束】** 每条被排除的源必须留证：`records/gate/<版本>-gate.json` 中记录 `id`、`api` 的 host、判定结论、命中词、证据摘要（分类名或标题的哈希，禁止明文摘录成人标题）、处理动作、日期。

**CAT-SEC-006【规范约定】** 门禁是发布流程的前置步骤，不是事后检查：未产出 `gate.json` 的版本不得发布（CAT-NAM-003）。

## 12 探活标准

### 12.1 形态分流

**CAT-PRB-001【硬约束】** 三类对象分别探活，不得用同一套判据：`type=0` 走 maccms HTTP 探活；`type=1` 走 JS 契约探活；`lives[]` 走播放列表探活。

### 12.2 maccms 探活

**CAT-PRB-002【硬约束】** 端点、超时、重试、采样上限：

| 项 | 规定 |
|----|------|
| 端点1 | `<api>?ac=list`（取分类、pagecount、首页列表；`api` 自带末尾斜杠时直接接 `?`） |
| 端点2 | `<api>?ac=detail&ids=<端点1返回的第一个非空 vod_id>` |
| 端点3 | `<api>?ac=detail&wd=<固定关键词>&pg=1`，固定关键词用 `庆余年` |
| 连接超时 | 5 秒 |
| 总超时 | 10 秒 |
| 重试 | 每端点最多 2 次，间隔 ≥1 秒；仅对超时、5xx、DNS 失败重试，4xx 不重试 |
| 采样上限 | 每源 ≤6 个请求（3 个端点各最多 2 次）；一轮全量 ≤ 源数 × 6 |
| 请求头 | 统一 `User-Agent: Mozilla/5.0`，不带 Cookie、不带 Referer |
| 代理 | 仅对 `gfw=true` 且本地直连失败的源走代理，并在记录中标注「代理环境」 |

**CAT-PRB-003【硬约束】** 四档结论判据：

| 档位 | 判据（同时满足） |
|------|------------------|
| 可用 | 3/3 端点通过：`ac=list` 返回 200 且可解析；分类数 ≥5；`pagecount` ≥100；`total` ≥1000；端点2 返回 `vod_play_url` 且至少 1 条 `http(s)` 链接；端点3 返回 ≥1 条；3 个端点的中位耗时 ≤3000 ms |
| 间歇 | 2/3 端点通过；或中位耗时 3000-8000 ms；或出现单次超时/单次 5xx 但重试后成功；或搜索偶发 0 条 |
| 不可用 | ≤1/3 端点通过；或 `pagecount=0`；或返回体不是 maccms 结构；连续两轮（间隔 ≥24 小时）均满足才判「死亡」 |
| 无法判定 | 403/429/验证码/证书错误/返回 HTML 站点页/需代理但代理不可用 |

**CAT-PRB-004【规范约定】** 判据中的 `total` 用于识别「空库」：分类存在但 `total` 极低（如 <1000）的源按「间歇」处理并标注「疑似空库」，不得计入可用源。

**CAT-PRB-005【规范约定】** 探活脚本可用 PowerShell 实现（Windows 环境），单源示例：

```powershell
$api = '<api>'
$sw = [Diagnostics.Stopwatch]::StartNew()
try {
  $r = Invoke-WebRequest -Uri ($api + '?ac=list') -TimeoutSec 10 -UseBasicParsing -Headers @{ 'User-Agent' = 'Mozilla/5.0' }
  $sw.Stop()
  $o = $r.Content | ConvertFrom-Json
  "{0} 状态={1} 耗时={2}ms 分类={3} pagecount={4} total={5}" -f $api, $r.StatusCode, $sw.ElapsedMilliseconds, $o.class.Count, $o.pagecount, $o.total
} catch {
  $sw.Stop()
  "{0} 失败={1} 耗时={2}ms" -f $api, $_.Exception.Message, $sw.ElapsedMilliseconds
}
```

### 12.3 JS 源探活

**CAT-PRB-006【规范约定】** JS 源必须在本地运行环境中跑完整契约，不允许只做「HTTP 200」判定：

| 项 | 规定 |
|----|------|
| 运行环境 | Node ≥20 或 Bun ≥1.1；用示例工程 `utils.ts` 的测试环境构造 `env`/`req` 垫片 |
| 方法覆盖 | `getCategory`、`getHome`（page=1 与 page=2）、`getSearch`（固定关键词）、`getDetail`（取首页第一条 `id`） |
| 通过判据 | 分类 ≥1；首页每页 ≥10 条且两页无重复；搜索 ≥1 条；详情 `playlist` ≥1 且 `videos` 全为可播形态 |
| 耗时 | 单方法 ≤10 秒；连续 2 次失败判该源不可用 |
| 记录 | 每源输出 `records/probe/js-<id>.json`，含每方法条数、耗时、异常栈首行 |

**CAT-PRB-007【规范约定】** JS 源若使用 iframe，必须额外验证 `parseIframe` 返回 `https?://` 开头且以 `.m3u8` 或 `.mp4` 结尾的地址；返回空则按「降级」记录，不得判通过。

### 12.4 直播探活

**CAT-PRB-008【规范约定】** `lives[]` 探活：GET `url`，连接 5 秒/总 10 秒，最多 2 次；判据：

- `type=0`：响应包含 `#EXTM3U`，且 `#EXTINF` 数量 ≥20 判可用；1-19 判间歇；0 判不可用。
- `type=1`：响应按行可解析出 `分组,#genre#` 与频道行，频道行 ≥20 判可用；同 m3u 分档。
- 抽样：从频道列表中随机取 3 个频道地址做 HEAD 请求，全部 200 判「可播抽样通过」，任一失败记「抽样不可播」并降档到间歇。

| caiji.dyttzyapi.com | JSON | 32 | 4252 | 85027 | 2071 ms |
| cj.lziapi.com | JSON | 40 | 8148 | 162951 | 2017 ms |
| cj.ffzyapi.com | XML | 31 | 4950 | 98997 | 1089 ms |

结论：`class≥5`、`pagecount≥100`、`total≥1000`、中位 ≤3000 ms 的阈值在上述真实源上可区分可用与慢源；XML 与 JSON 两种形态均可解析。

### 12.6 速度分档、命名与排序

**CAT-PRB-011【规范约定】** 档位按三个端点（`ac=list`、详情、搜索）的耗时算术平均值划分：

| 档位 | 判据 | 处置 |
|------|------|------|
| 极速 | 均值 ≤800 ms | 正常发布，名称前缀 `极速｜` |
| 快速 | 均值 800-1500 ms | 正常发布，名称前缀 `快速｜` |
| 标准 | 均值 1500-2500 ms | 正常发布，名称前缀 `标准｜` |
| 慢速 | 均值 2500-4000 ms | 仅在源数不足 5 条时补齐，名称前缀 `慢速｜` |
| 不纳入 | 均值 >4000 ms，或任一端点不通过 | 不进入样板线路；如需保留，按 CAT-PRB-003 记为间歇并单独登记 |

取均值而不取中位数：搜索端点在分类多、库容量大的源上天然最慢，中位数会把它掩盖成「极速」，导致名称失真（E：龙马资源 搜索 3680 ms、中位数 193 ms）。

不对「单端点耗时」设否决线：单次采样噪声可达 ±1500 ms，按单端点否决会误杀正常源（E：龙马资源 同一源连续两轮 detail 191/3186 ms、搜索 3680/4008 ms）。慢端点的影响已由均值体现，源是否可用由 CAT-PRB-003 的四档判据另行裁定。

**CAT-PRB-012【规范约定】** 点播源 `name` 固定为 `档位｜站点名`，档位只允许 `极速`、`快速`、`标准`、`慢速`；档位复核后变化时只改 `name`，不改 `id`。依据：小猫无源分组能力（CAT-CFG-007），只能把档位编码进名称；与直播的 `分组｜名称` 共用全角竖线，但档位与分组是两套枚举，不得混用。

**CAT-PRB-013【规范约定】** 配置数组顺序按档位由快到慢排列，同档按三端点耗时均值升序，均值完全相同时按 `id` 字典序；客户端是否按配置顺序展示标【待验证】（V19）。即使客户端重排，配置文件本身也必须自解释档位与快慢。

**CAT-PRB-014【硬约束】** 探活耗时必须在同一网络环境下按「首轮成功」的耗时记录，禁止用重试后的最快值美化档位；重试成功但首轮失败的源按 CAT-PRB-003 降为间歇，不参与档位排序。

## 13 修复与回归

**CAT-PRC-006【规范约定】** 失效分三类，处置不同：

- 结构性失效：域名解析失败、证书过期、`api` 路径变更。处置：换域名/换路径，保留 `id`，`name` 加 `·备线` 或直接替换主源。
- 上游空库：接口正常但 `pagecount=0` 或分类全空。处置：标注「上游停更」，降为间歇，不伪造数据。
- 配置失效：`id` 重复、`type` 错、`extra.js` 语法错误。处置：按本规范改配置并重跑探活。

**CAT-PRC-007【硬约束】** 禁止伪造上游数据（包括写死列表、伪造 `pagecount`、用截图代替实测）；禁止修改客户端本地缓存或其他应用的数据目录来掩盖上游问题。

**CAT-PRC-008【规范约定】** 修复顺序：复现（记录时间、源、请求）→ 定位（区分客户端/配置/上游）→ 最小改动 → 单源探活 → 回归 → 留证。禁止在未复现的情况下直接改配置。

**CAT-PRC-009【硬约束】** 回归清单，逐条勾选：

| 编号 | 场景 | 通过判据 |
|------|------|----------|
| G1 | 源列表 | 添加该 URL 后，源出现在列表，名称与 `id` 正确 |
| G2 | 首页 | 首页有内容，封面可加载，无空白分区 |
| G3 | 分类 | 切换 3 个分类（含空分类）均有合理结果或明确空态 |
| G4 | 翻页 | 第 2、3 页有内容且与第 1 页不重复 |
| G5 | 详情 | 剧集列表完整，线路数与上游一致 |

## 14 验收标准

**CAT-PRC-011【硬约束】** 配置层校验（脚本可判定，全部为 0 才通过）：
