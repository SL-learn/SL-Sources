# 仓库通用规范

> 位置：`规范/仓库通用规范.md`｜地位：仓库级强制条款的正本。

> 章节号沿用拆分前 README 的编号，便于与历史提交对照。
> 条款编号格式 `<应用>-<类别>-<三位序号>`；编号一经发布即冻结，规则见第 17 章。

> 当前版本：v1.1（2026-11-12）。v1.0 为 2026-11-07 结构重整时的定稿，此前本文无版本号。

## 1. 定位与范围

### 1.1 定位

| 项 | 内容 |
|---|---|
| 是什么 | 个人自用的影视/直播源仓库；包含配置、脚本、jar 与探活记录，可本地安装，也可在线直拉 |
| 给谁用 | 仓库所有者本人及其家庭设备；不做公开运营、不做付费分发 |
| 部署形态 | 本地目录（`/sdcard/TVBox/<包id>/`）+ 在线直链（GitHub / Gitee，jsDelivr 仅加速） |
| 内容形态 | 一个包内含多条线路（综合 / 少儿 / 长辈），在客户端「线路选择」里切换 |

### 1.2 范围外（明确不做）

| 编号 | 不做的事 |
|---|---|
| SYS-PRC-001 | 不编写新的爬虫实现，不逆向、不破解第三方付费或鉴权接口 |
| SYS-PRC-002 | 成人内容按「源」分流：以成人内容为主体的源单独成文件、放非公开台账、不进入本仓；普通源内夹带的成人分类保留并置后标注，不按分类屏蔽。应用规范可在此之上更严（TVBox 现行仍按 `规范/TVBox 源规范.md` 做分类封闭） |
| SYS-PRC-003 | 不收录网盘、盘搜、云盘转存类站点 |
| SYS-PRC-004 | 不伪造上游数据、不伪造探活结论、不把「无法判定」写成「可用」 |
| SYS-PRC-005 | 不做商业售卖、引流、代充、二次分发收费 |

## 3. 仓库架构与应用分层

### 3.1 目标结构

一个应用一层，**不再有 `packages/<包id>/` 包裹层**。应用目录内的文件即发布物。

```text
<仓库根>/
├── README.md                    D01 入口：是什么、目录地图、维护链
├── 文档索引.md                   D06 文档地图（≤30 行）
├── 决策记录.md                   D08 拍板记录（只追加）
├── 声明.md  LICENSE  .gitignore  D09 合规与免责
├── apps/                        成品：apps/<应用>/（版本与条数唯一来源 version.json）
├── 规范/                        D03 人读强制条款（编号化）
├── 使用/                        D02 客户端怎么填、怎么装、怎么切线路
├── 规则/                        机读判据与阈值（平台地址.json、包内白名单.json）
├── 清单/                        D07 台账 CSV：应用清单、包清单、版本对照表
├── 变更/                        D04 CHANGELOG-<应用>.md + 映射表
├── 记录/README.md               D05 只放版本事实指针；过程数据落文字结论后即删
├── 归档/                        只读历史文档 + 索引.csv（旧文档不删，只归档；过程数据不入此）
├── 发布/                        D10 发布说明、构建说明、地址、地址模板；便携包导出到工作区，不入库
└── 工具/                        D11 只放 README.md 指针；脚本本体在仓外工作区
```

| 编号 | 规则 |
|---|---|
| SYS-STR-001 | 应用必须落在 `apps/<应用id>/`，应用内必须自带 `README.md` 与 `version.json`；禁止把应用文件放到仓库根 |
| SYS-STR-002 | 新增应用 = 新建 `apps/<应用id>/` + 在 `文档索引.md` 登记；**不得改动既有应用** |
| SYS-STR-003 | 应用目录内禁止再套 `packages/`、`dist/` 之类的包裹层；发布物直接放在应用目录下 |
| SYS-STR-004 | 应用内一切引用只用相对路径；禁止跨应用引用（不写 `../../`、不写指向其他应用目录的绝对地址） |
| SYS-STR-005 | 应用 id：小写 ASCII，`[a-z][a-z0-9]{2,15}`；现有 `tvbox`、`catmovie`、`reading` |
| SYS-STR-006 | 线路目录：ASCII 短名，固定 `std`/`kids`/`elders`；中文只用于配置内显示名与客户端线路名 |
| SYS-STR-007 | 线路代号（`std`/`kid`/`eld`）用于站点 key 前缀，**与目录名解耦**；key 一旦发布不再改动 |
| SYS-STR-008 | 应用的唯一登记物是 `apps/<应用id>/README.md` 与 `version.json`；仓库内不另设应用级登记表 |

### 3.2 文档分层

一份信息只允许有一个权威出处；其他位置只写「见 X 文档第 N 节」。

| 类别 | 位置 | 只写什么 | 不写什么 |
|---|---|---|---|
| 介绍 | `README.md` | 这是什么、有哪些应用、入口地址、目录导览、动手前必读顺序 | 条款、变更流水、实测数据 |
| 使用 | `使用/` | 客户端怎么填地址、本地包怎么放、怎么切线路、常见问题 | 内部判据与维护流程 |
| 规范（人读） | `规范/` | 强制条款（编号化）、验收标准、命名与结构要求 | 操作步骤流水 |
| 规则（机读） | `规则/` | 检测/修复用的判据与阈值，工具直接读取 | 解释性长文 |
| 流程 | `工具/<工具名>/说明.md` | 生成、检测、发布三套操作步骤与开关含义 | 重复规范条款，只引用条款号 |
| 变更 | `变更/CHANGELOG-<应用>.md` | 版本号、日期、改了什么、为什么 | 改写历史行 |
| 日志（非公开） | 非公开域 `记录/YYYY-MM-DD/<应用>/` | 只写文字结论：时间、现象、判定、证据摘要 | 原始截图、日志、体检表长期留存 |

| 编号 | 规则 |
|---|---|
| SYS-DOC-001 | 一条规则只允许写一处；应用级文档引用条款号，不得复制正文 |
| SYS-DOC-002 | 应用级文档与仓库级冲突时，以仓库级为准；例外必须在 `决策记录.md` 登记 |
| SYS-DOC-003 | 新增任何文档必须先登记到 `文档索引.md`，未登记视为无效文档 |
| SYS-DOC-009 | 只保留三类内容：**方法类**（规范、规则、测试规范、坑位库）、**成果类**（成品源、版本、地址）、**结论类**（文字结论：时间、现象、判定、证据摘要）。截图、日志、临时导出、中间体检表、一次性导出副本，在结论落档后**直接删除**，不留在公开仓、私有仓，也不留在工作区归档。观察池等「下次接着测」的状态台账属结论类，保留 |
| SYS-DOC-010 | 结论必须先落文字再删证据。删除截图、日志、导出件前，须把时间、现象、判定与证据摘要写成可复现判断的文字记录，做到不依赖图片即可复核；没有文字结论的过程数据不得作为「已留档」保留 |

### 3.4 对外路径冻结

| 编号 | 规则 |
|---|---|
| SYS-DIST-001 | 所有对外分享的路径与文件名**永久固定**，禁止写入版本号或日期（禁 `api_v1.2.json`、`tvboxSL_20261107/`、`spider_2.0.jar`、`-latest` 等）；改版只改内容，不改路径 |

### 3.5 双平台地址维护

GitHub 与 Gitee 的 raw 基址不同。因此两平台地址**同源生成、并列给出**：`发布/地址.md` 与四个 README 的受管地址块由渲染脚本一次写入两平台全部地址，其余文档只写仓库内相对路径。

| 编号 | 规则 |
|---|---|
| SYS-DIST-002 | 平台基址只允许定义在 `规则/平台地址.json` 一处；文档、脚本、配置**禁止写死任一平台的绝对地址**，禁止把 GitHub 地址原样推到 Gitee（含 README、使用说明、目录说明、规范示例、脚本默认值） |
| SYS-DIST-003 | 唯一允许按平台不同的产物有两个：`apps/tvbox/api_index.json`、`apps/tvbox/api_all.json`；`发布/地址.md` 与各 README 的受管地址块两平台并列、内容一致，其余文件两平台必须字节一致（`使用/TVBox 使用说明.md` TVB-DIST-011 为其应用级落地） |
| SYS-DIST-004 | 渲染入口固定 `工具/发布/渲染.py --platform github|gitee`：由 `规则/平台地址.json` 取两平台基址 → 按 `--platform` 重算 `api_index.json`/`api_all.json` → 由 `发布/地址模板.md` 渲染两平台并列的 `发布/地址.md`，并把地址块写入 README 的受管标记之间；占位符统一 `{{GITHUB_RAW}}`/`{{GITEE_RAW}}`/`{{平台名称}}` 等，模板内不得出现任一平台域名 |
| SYS-DIST-005 | 渲染时机只在推送前：GitHub 线由 `工具/发布/发布.ps1` 在本地 `main` 渲染后推送 `origin main`；Gitee 线在**临时 worktree** 内基于本地 `gitee` 分支，先 `git read-tree -u --reset main` 把树整体拉齐，再 `渲染.py --platform gitee`，提交为快照后推送 `gitee:main`。两条分支互不合并，推送后删除临时 worktree；本地工作区（`main`）绝不因渲染被污染 |
| SYS-DIST-006 | 面向用户的绝对地址只允许出现在两处：`发布/地址.md`，以及根 `README.md` 与 `apps/*/README.md` 中**受管地址块**（`<!-- 地址块开始 -->` 与 `<!-- 地址块结束 -->` 之间，由渲染脚本写入，禁止手改）。其他文档引用本仓文件一律写仓库内相对路径，需要地址时写「见 `发布/地址.md`」。`发布/地址.md` 必须在 `文档索引.md` 登记 |
| SYS-DIST-007 | 推送禁止 `--force`、禁止改写已有历史、禁止删除或移动旧 tag。两平台分支**独立维护、互不合并**：GitHub 用 `main`；Gitee 远端同为 `main`，由本地 `gitee` 分支重建树后推送（`git push gitee gitee:main`）。禁止把一端的渲染提交合并到另一端，禁止使用任何 `ours` 策略吞并冲突 |
| SYS-DIST-008 | 发布验收两条：① `python 工具/发布/渲染.py --check --platform <平台>` 通过（受管地址块之外无写死的仓库绝对地址、无另一平台域名、`发布/地址.md` 含两平台基址且不把 451 路径当可用地址、README 地址块为最新）；② 两平台各自的 raw 实测 200，站点数/条数与本地一致。任一条不通过不得发布 |
| SYS-DIST-009 | Gitee 版 `apps/tvbox/api_index.json` 的三条线路分别为：综合 → `apps/tvbox/api_all.json`（`apps/tvbox/std/api.json` 被 Gitee 451 内容审核拦截，综合改用合并文件），少儿 → `apps/tvbox/kids/api.json`，长辈 → `apps/tvbox/elders/api.json`，三条线路地址互不相同。GitHub 版仍为三条线路各自地址。各线路站点数以 `apps/tvbox/version.json` 的 `lines` 为准，禁止在条款里另抄数字。该差异由 `工具/源生成/生成.py` 按 `--platform` 决定，禁止在产物里手改。综合线路含少儿/长辈重复站点，属合并文件固有形态，不算缺陷 |
| SYS-DIST-010 | 分支模型固定：GitHub 线 `main`（源码 + GitHub 渲染产物，唯一人工入口）；Gitee 线为整仓镜像，树 = `main` 树 + Gitee 渲染产物。Gitee 首次快照的父提交必须是当时的 `gitee/main`，此后每次快照父提交为上一次快照，保证推送恒为 fast-forward；禁止用 orphan 重建（首次会要求 force） |
| SYS-DIST-011 | 平台 tag：主 tag `<应用id>-v<主>.<次>.<修订>` 只打 `main`、只推 GitHub；平台快照 tag `<应用id>-v<主>.<次>.<修订>-gitee` 只打本地 `gitee`、只推 Gitee。两平台禁止同名异指，拉取 Gitee 时必须 `--no-tags` |
| SYS-DIST-012 | 便携版导出：产物目录内 `api_index_rel.json` 的三条 url 必须全部以 `./` 开头；`jar` 字段必须相对；导出脚本必须重写 `api_all.json` 的绝对引用，并按 `规则/平台地址.json` 生成「本仓自指地址清单」（两平台 raw 前缀、GitHub 网页前缀、jsDelivr 前缀）后逐文本文件扫描，命中即失败。运行时依赖（js 库、播放引擎、远程 jar、`ext` 依赖、内容清单）必须抓取进包并改写为相对引用，扫描按「运行时引用 / 注释声明」分层：运行时未本地化即失败；注释、版权声明里的地址保留原样、不改写；仅图标等经确认无法以相对路径加载的项可列例外并注明原因。内容快照须在包内说明标注抓取时间与刷新方式。导出产物不入库 |
| SYS-DIST-013 | 多线路索引（`api_index.json` / `api_index_local.json` / `api_index_rel.json`）的 `urls` 内 `url` **必须唯一**，禁止两条及以上线路指向同一文件或同一地址：客户端按 url 区分线路并只缓存一份配置，重复 url 会导致切换后站点列表不变。`工具/发布/渲染.py --check` 必须校验「去重后长度 == 线路数」，重复即门禁失败；发布验收必须逐线路按索引实际 url 实测站点数，任一线路重复、不可用或站点数与登记不符即不通过 |

## 10. 版本、校验与缓存

| 编号 | 规则 |
|---|---|
| SYS-VER-001 | 包版本 semver `主.次.修订`；新增/下架站点、换 jar、改线路结构均升**次**版本；仅修错别字升修订 |
| SYS-VER-002 | `version.json` 必须与 `变更/CHANGELOG-<应用>.md` 末条、`清单/版本对照表.csv` 末行一致；不一致阻断发布。README、发布说明、文档索引不得抄写具体版本号与条数 |
| SYS-VER-003 | jar 内容一变，引用处 md5 必须同时变；md5 不变等于用户永远拿不到新文件（TVB-CFG-004） |
| SYS-VER-004 | 不带 md5 的 jar 引用一律不合格（尽管客户端会按 3 天缓存兜底） |
| SYS-VER-005 | 配置不设 md5；客户端每次启动拉取，失败回退缓存；更新生效时间受 CDN 缓存影响【待验证：GitHub raw / Gitee raw 的 TTL】 |
| SYS-VER-006 | 回滚以 tag 为单位：打 `v<版本>` 标签，入口地址可临时指向该 tag；不得用「改回文件内容但不改版本号」的方式回滚 |
| SYS-VER-007 | 发布说明必须记录：新增/下架站点数、失效修复项、门禁处置项、版本号 |

**不满足的处理**：SYS-VER-002/SYS-VER-003 违反 → 阻断发布；SYS-VER-006 违规回滚 → 记入记录并在下一版纠正。

### 10.1 版本与历史（如何回看旧版）

版本号只存在于 `version.json` 与 Git tag，**不进任何对外路径**（SYS-DIST-001/SYS-VER-011）。

| 编号 | 规则 |
|---|---|
| SYS-VER-008 | 应用 tag 固定 `<应用id>-v<主>.<次>.<修订>`，与该应用 `version.json` 完全一致，只打 `main`、只推 GitHub；平台快照 tag 固定 `<应用id>-v<主>.<次>.<修订>-gitee`，只打本地 `gitee` 分支、只推 Gitee；仓库级 tag 固定 `repo-v<主>.<次>.<修订>`，只记录整体发布、只推 GitHub。以上 tag 都只增不移不覆盖 |
| SYS-VER-009 | 每次发版后，在 `清单/版本对照表.csv` **追加**一行：应用、版本号、短 SHA、日期、站点数；旧行不得改写 |
| SYS-VER-010 | 回溯旧版用固定 commit 或 tag 的 raw 地址，不改入口路径 |
| SYS-VER-011 | 版本只允许出现在四处：`apps/<应用>/version.json`、`清单/版本对照表.csv`、主 tag `<应用id>-v<主>.<次>.<修订>`、平台快照 tag `<应用id>-v<主>.<次>.<修订>-gitee`。README、发布说明、文档索引一律引用，不得再抄。标签一旦打过不再移动。历史 `tvboxSL-v1.0.x` 保留不改名 |

三种回溯方式与真实示例：

| 方式 | 用法 | 实例（实测 200，`<owner>` 见 `规则/平台地址.json`） |
|---|---|---|
| ① 提交历史 | 平台网页 / 客户端查看 `apps/tvbox/` 历史 | `<平台网页基址>/commits/main/apps/tvbox` |
| ② tag 列表 | 列出后点选版本 | `<平台网页基址>/tags` |
| ③ 固定 SHA / tag 的 raw | 把 `main` 换成 tag 或短 SHA | `<平台 raw 基址>/tvbox-v1.0.2/apps/tvbox/version.json`（Gitee 用平台快照 tag `tvbox-v1.0.2-gitee` 或 Gitee 快照短 SHA，由 `规则/平台地址.json` 的 `raw模板` 生成） |
| ④ jsDelivr 固定 tag（仅 GitHub） | 比 `@main` 更适合复现，且可长期缓存 | `<jsDelivr 基址>@tvbox-v1.0.2/apps/tvbox/api_all.json` |

各平台的真实基址与可直接填写的地址见仓库根 `发布/地址.md`（两平台并列）与各 README 的受管地址块，本文档不写死任一平台地址（SYS-DIST-002）。

**缓存提示（很重要）**：GitHub raw 对同一路径有 CDN 缓存（实测推完 `main` 后，同一路径仍返回上一版内容，而 tag 路径已是新版），jsDelivr `@main` 最长缓存 12 小时、`@<tag>` 永久。
因此**刚推完立刻测到旧内容属正常延迟，不是发布失败**；确认新版的可靠做法是用 tag / 固定 SHA 地址比对，或等 5–10 分钟后重试 `main`。升级 jar 时因引用带 md5，客户端不会误用旧缓存（TVB-CFG-004）。
