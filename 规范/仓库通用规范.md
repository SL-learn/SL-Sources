# 仓库通用规范

> 位置：`规范/仓库通用规范.md`｜地位：仓库级强制条款的正本。

> 章节号沿用拆分前 README 的编号，便于与历史提交对照。
> 条款编号格式 `<应用>-<类别>-<三位序号>`；编号一经发布即冻结，规则见第 17 章。

## 1. 定位与范围

### 1.1 定位

| 项 | 内容 |
|---|---|
| 是什么 | 个人自用的影视/直播源仓库；包含配置、脚本、jar 与探活记录，可本地安装，也可在线直拉 |
| 给谁用 | 仓库所有者本人及其家庭设备；不做公开运营、不做付费分发 |
| 部署形态 | 本地目录（`/sdcard/TVBox/<包id>/`）+ 在线直链（GitHub / Gitee，jsDelivr 仅加速） |
| 内容形态 | 一个包内含多条线路（综合 / 少儿 / 长辈），在客户端「线路选择」里切换 |

### 1.2 范围外（明确不做）

| 编号 | 不做的事 |
|---|---|
| SYS-PRC-001 | 不编写新的爬虫实现，不逆向、不破解第三方付费或鉴权接口 |
| SYS-PRC-002 | 不聚合、不链接任何成人内容；不保留任何成人站点，即使来源包已标注 |
| SYS-PRC-003 | 不收录网盘、盘搜、云盘转存类站点 |
| SYS-PRC-004 | 不伪造上游数据、不伪造探活结论、不把「无法判定」写成「可用」 |
| SYS-PRC-005 | 不做商业售卖、引流、代充、二次分发收费 |

## 3. 仓库架构与应用分层

### 3.1 目标结构

一个应用一层，**不再有 `packages/<包id>/` 包裹层**。应用目录内的文件即发布物。

```text
<仓库根>/
├── README.md              ← 介绍：这是什么、有哪些应用、入口、目录导览
├── 文档索引.md             ← 一张表：路径 / 职责 / 读者 / 更新时机
├── 决策记录.md             ← 拍板项 + 理由 + 日期
├── 声明.md  LICENSE  .gitignore
├── 规范/                   ← 人读的强制条款（编号化）
├── 使用/                   ← 客户端怎么填、怎么装、怎么切线路
├── 规则/                   ← 机读判据与阈值（工具直接读取）
├── 变更/CHANGELOG-<应用>.md ← 只追加的版本流水
├── 记录/YYYY-MM-DD/<应用>/  ← 每次检测报告、探活、体检表
├── 工具/
│   ├── 源生成/              ← 一条命令重建全部产物
│   └── 源检测/              ← 检测、修复、门禁
├── apps/
│   ├── tvbox/              ← 索引 + 线路目录 + 共用 jar
│   │   ├── README.md  version.json  目录说明.txt
│   │   ├── api_index.json  api_index_local.json  api_all.json
│   │   ├── _common/jar/
│   │   └── std/  kids/  elders/
│   ├── catmovie/           ← config.json + README + version.json
│   └── reading/            ← 书源/订阅源规则与模板（个人源不入库）
└── _分析/                   ← 本地分析产物，.gitignore 排除
```

| 编号 | 规则 |
|---|---|
| SYS-STR-001 | 应用必须落在 `apps/<应用id>/`，应用内必须自带 `README.md` 与 `version.json`；禁止把应用文件放到仓库根 |
| SYS-STR-002 | 新增应用 = 新建 `apps/<应用id>/` + 在 `文档索引.md` 登记；**不得改动既有应用** |
| SYS-STR-003 | 应用目录内禁止再套 `packages/`、`dist/` 之类的包裹层；发布物直接放在应用目录下 |
| SYS-STR-004 | 应用内一切引用只用相对路径；禁止跨应用引用（不写 `../../`、不写指向其他应用目录的绝对地址） |
| SYS-STR-005 | 应用 id：小写 ASCII，`[a-z][a-z0-9]{2,15}`；现有 `tvbox`、`catmovie`、`reading` |
| SYS-STR-006 | 线路目录：ASCII 短名，固定 `std`/`kids`/`elders`；中文只用于配置内显示名与客户端线路名 |
| SYS-STR-007 | 线路代号（`std`/`kid`/`eld`）用于站点 key 前缀，**与目录名解耦**；key 一旦发布不再改动 |
| SYS-STR-008 | 应用的唯一登记物是 `apps/<应用id>/README.md` 与 `version.json`；仓库内不另设应用级登记表 |

### 3.2 文档分层

一份信息只允许有一个权威出处；其他位置只写「见 X 文档第 N 节」。

| 类别 | 位置 | 只写什么 | 不写什么 |
|---|---|---|---|
| 介绍 | `README.md` | 这是什么、有哪些应用、入口地址、目录导览、动手前必读顺序 | 条款、变更流水、实测数据 |
| 使用 | `使用/` | 客户端怎么填地址、本地包怎么放、怎么切线路、常见问题 | 内部判据与维护流程 |
| 规范（人读） | `规范/` | 强制条款（编号化）、验收标准、命名与结构要求 | 操作步骤流水 |
| 规则（机读） | `规则/` | 检测/修复用的判据与阈值，工具直接读取 | 解释性长文 |
| 流程 | `工具/<工具名>/说明.md` | 生成、检测、发布三套操作步骤与开关含义 | 重复规范条款，只引用条款号 |
| 变更 | `变更/CHANGELOG-<应用>.md` | 版本号、日期、改了什么、为什么 | 改写历史行 |
| 日志 | `记录/YYYY-MM-DD/<应用>/` | 逐次检测报告、探活结果、体检表、修复 diff | 结论性规范 |

| 编号 | 规则 |
|---|---|
| SYS-DOC-001 | 一条规则只允许写一处；应用级文档引用条款号，不得复制正文 |
| SYS-DOC-002 | 应用级文档与仓库级冲突时，以仓库级为准；例外必须在 `决策记录.md` 登记 |
| SYS-DOC-003 | 新增任何文档必须先登记到 `文档索引.md`，未登记视为无效文档 |

### 3.3 应用一览

| 应用 | 入口格式 | 发布物 | 说明 |
|---|---|---|---|
| `tvbox` | `api_index` | `api_index.json` / `api_index_local.json` / `api_all.json` | 三条线路 std/kids/elders |
| `catmovie` | `maccms_json` | `config.json`（单文件全量） | 只有 maccms 与 JS 两种源 |
| `reading` | `book_source` | 规则与模板 | 个人书源/订阅源不入公开仓 |

`入口格式` 取值：`api_index`（TVBox）、`maccms_json`（小猫影视）、`book_source`（阅读）。

### 3.4 对外路径冻结

| 编号 | 规则 |
|---|---|
| SYS-DIST-001 | 所有对外分享的路径与文件名**永久固定**，禁止写入版本号或日期（禁 `api_v1.2.json`、`tvboxSL_20261107/`、`spider_2.0.jar`、`-latest` 等）；改版只改内容，不改路径 |

## 10. 版本、校验与缓存

| 编号 | 规则 |
|---|---|
| SYS-VER-001 | 包版本 semver `主.次.修订`；新增/下架站点、换 jar、改线路结构均升**次**版本；仅修错别字升修订 |
| SYS-VER-002 | `version.json` 必须与 `变更/CHANGELOG-<应用>.md` 末条、`发布说明.md` 一致；不一致阻断发布 |
| SYS-VER-003 | jar 内容一变，引用处 md5 必须同时变；md5 不变等于用户永远拿不到新文件（TVB-CFG-004） |
| SYS-VER-004 | 不带 md5 的 jar 引用一律不合格（尽管客户端会按 3 天缓存兜底） |
| SYS-VER-005 | 配置不设 md5；客户端每次启动拉取，失败回退缓存；更新生效时间受 CDN 缓存影响【待验证：GitHub raw / Gitee raw 的 TTL】 |
| SYS-VER-006 | 回滚以 tag 为单位：打 `v<版本>` 标签，入口地址可临时指向该 tag；不得用「改回文件内容但不改版本号」的方式回滚 |
| SYS-VER-007 | 发布说明必须记录：新增/下架站点数、失效修复项、门禁处置项、版本号 |

**不满足的处理**：SYS-VER-002/SYS-VER-003 违反 → 阻断发布；SYS-VER-006 违规回滚 → 记入记录并在下一版纠正。

### 10.1 版本与历史（如何回看旧版）

版本号只存在于 `version.json` 与 Git tag，**不进任何对外路径**（SYS-DIST-001/SYS-VER-011）。

| 编号 | 规则 |
|---|---|
| SYS-VER-008 | 应用 tag 固定 `<应用id>-v<主>.<次>.<修订>`，与该应用 `version.json` 完全一致；仓库级 tag 固定 `repo-v<主>.<次>.<修订>`，只记录整体发布；两者都只增不移不覆盖 |
| SYS-VER-009 | 每次发版后，在 `记录/版本对照表.csv` **追加**一行：应用、版本号、短 SHA、日期、站点数；旧行不得改写 |
| SYS-VER-010 | 回溯旧版用固定 commit 或 tag 的 raw 地址，不改入口路径 |
| SYS-VER-011 | 版本只存在于两处：`version.json` 内的版本号；Git tag `<应用id>-v<主>.<次>.<修订>`。标签一旦打过不再移动。历史 `tvboxSL-v1.0.x` 保留不改名 |

三种回溯方式与真实示例：

| 方式 | 用法 | 实例（实测 200） |
|---|---|---|
| ① 提交历史 | GitHub 网页 / 客户端查看 `apps/tvbox/` 历史 | `https://github.com/SL-learn/SL-Sources/commits/main/apps/tvbox` |
| ② tag 列表 | 列出后点选版本 | `https://github.com/SL-learn/SL-Sources/tags` |
| ③ 固定 SHA / tag 的 raw | 把 `main` 换成 tag 或短 SHA | `https://raw.githubusercontent.com/SL-learn/SL-Sources/tvbox-v1.0.2/apps/tvbox/version.json` |
| ④ jsDelivr 固定 tag | 比 `@main` 更适合复现，且可长期缓存 | `https://cdn.jsdelivr.net/gh/SL-learn/SL-Sources@tvbox-v1.0.2/apps/tvbox/api_all.json` |

**缓存提示（很重要）**：GitHub raw 对同一路径有 CDN 缓存（实测推完 `main` 后，同一路径仍返回上一版内容，而 tag 路径已是新版），jsDelivr `@main` 最长缓存 12 小时、`@<tag>` 永久。
因此**刚推完立刻测到旧内容属正常延迟，不是发布失败**；确认新版的可靠做法是用 tag / 固定 SHA 地址比对，或等 5–10 分钟后重试 `main`。升级 jar 时因引用带 md5，客户端不会误用旧缓存（TVB-CFG-004）。

## 15. 变更与维护

| 编号 | 场景 | 标准动作 |
|---|---|---|
| SYS-PRC-006 | 新增站点 | 进候选池 → 探活 → 门禁 → 判重 → 分配 key → 写入线路 → 回归该线路 → 升次版本 |
| SYS-PRC-007 | 下架站点 | 记录原因与证据 → 从 `sites` 删除 → 清理无引用 jar（TVB-STR-014）→ 回归 → 升次版本 |
| SYS-PRC-008 | 替换 jar | 计算新 md5 → 更新引用 → 更新 `md5.txt` → 回归引用该 jar 的全部站点 → 升次版本 |
| SYS-PRC-009 | 新增线路 | 新建目录（TVB-NAM-002）→ 写 `api.json` → 索引加一条 → `version.json` 加一条 → 跑单线路验收 → 升次版本 |
| SYS-PRC-010 | 新增应用 | 新建 `apps/<应用id>/` → `文档索引.md` 登记 → 跑整应用验收 → 从 `v1.0.0` 起版 |
| SYS-PRC-011 | 紧急回滚 | 入口指向上一 `v<版本>` tag → 发布说明记 `已回滚` → 24 h 内定位原因 |
| SYS-PRC-012 | 每次维护 | 必产出探活三件 + 冲突处置留痕（如有）+ 发布说明一节 |
| SYS-PRC-013 | 发布前 | 逐项跑第 14 章清单，缺项不发布 |

## 17. 编号冻结与文档编号规则

| 编号 | 规则 |
|---|---|
| SYS-DOC-004 | 条款编号固定格式 `<应用>-<类别>-<三位序号>`。应用码限 `TVB`/`CAT`/`RBS`/`RRS`/`SYS`/`DOC`；类别码限 `NAM`/`STR`/`CFG`/`CLS`/`PRB`/`VER`/`DIST`/`SEC`/`PRC`/`DOC`，不得自造 |
| SYS-DOC-005 | 编号发布后即冻结：不复用、不回收。条款废弃时保留编号并标注 `[废弃]` 作为占位，禁止把编号让给新条款 |
| SYS-DOC-006 | 新增条款只能追加到本（应用,类别）段末尾的下一号，段内不跳号；确有预留或废弃，必须在 `变更/编号映射表.csv` 备注中写明原因与范围 |
| SYS-DOC-007 | 每份规范只负责本应用的编号段，不得在他应用文档中定义同段条款；跨应用共用规则只放 `SYS` 段 |
