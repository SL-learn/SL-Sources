## 2. 判据

### 2.1 结构层

| 项 | 通过线 |
|---|---|
| 三线路 `api.json` | 可解析；`sites` 数量与 `version.json` 一致 |
| 站点必填 | `key` / `name` / `type` / `api` 齐全；`key` 只含小写字母数字下划线 |
| `searchable` | 只允许数字 `0/1`；写 `false` 视为结构缺陷（会被吞后回落可搜索） |
| `spider` | jar 的 `;md5;` 后缀与文件本体 md5 一致 |
| 重复 | 同一 `key` 不得出现两次；同一后端只保留一条并附对比证据 |

### 2.2 功能层

| 级 | 通过线 |
|---|---|
| 加载 | `load` + `init` 无异常；返回可解析 JSON |
| 首页/分类 | 分类数 ≥ 1 且分类名可读（无 `�`、无连续拉丁乱码） |
| 分类下 | ≥ 2 个分类各取到 ≥ 1 条带 `vod_id`+`vod_name` 的条目 |
| 详情 | `vod_play_url` 非空，含至少 1 个「集名$地址」 |
| 搜索 | 关键词命中 ≥ 1 条，详情可打开 |

### 2.3 播放层

| 指标 | 通过线 |
|---|---|
| 首片延迟 | ≤ 3000 ms |
| 实测速率 | 记录值 |
| 码率 | 主清单 `BANDWIDTH` 或分片字节×8÷`EXTINF` |
| 10 秒断流 | ≤ 1 次 |
| 判档 | 流畅（≥×2）/ 一般（≥×1.5）/ 卡（<×1.5、首片 >3s 或断流 ≥2） |
| 内容确认 | 前 100 KB 命中 `#EXTM3U`/TS/`ftyp`/FLV，或 `Content-Type: video/*` |

### 2.4 稳定性层

| 项 | 值 |
|---|---|
| 轮数 | 2 轮；争议源加到 3 轮 |
| 轮间隔 | ≥ 60 秒 |
| 超时 | 首轮 10 秒，失败放宽 20 秒；jar 加载单独 60 秒 |
| 重试 | 单端点 2 次；GET 失败后 POST 回退 |
| 挂起线 | cms 30 秒、js 75 秒、py 45 秒、jar 60 秒；累计 90 秒看门狗强杀 |
| 判定 | 2 轮全通 = 稳定；1 轮 = 间歇；0 轮 = 不可用 |

### 2.5 能力分层（每条源必须归一层）

| 层 | 条件 | 处置 |
|---|---|---|
| A 可浏览 | 有分类且分类下有片，详情与播放正常 | 排在前面 |
| B 仅搜索 | 无分类或分类不可用，但搜索准、能播 | 保留，名称末尾（速度符号之后）加 `🔎`，`searchable` 写 `1`；整组置后（细则见 2.7） |
| C 待修复 | 能搜不能播，或分类与搜索都空 | 移入观察池，不留在成品占位 |

包装版（`type:3` + JS）与直连版必须分别跑 `home`/`category` 对照；直连有分类、包装没有，判包装回归，先修包装。

### 2.6 超时线口径与复核（2026-11-08 修订）

硬超时按形态分开，不能用一条线卡所有源：

| 形态 | 硬超时 | 理由 |
|---|---|---|
| cms | 30 秒 | 直连 maccms 三端点，超过 30 秒基本可判源侧慢 |
| js | **75 秒** | js 要跑 load→init→home→category→detail→playerContent 全链路，30 秒线偏紧 |
| py | 45 秒 | 需加载解释器与 spider 基类 |
| jar | 60 秒 | 加载 jar 本身耗时 |

**超时 ≠ 不可用。** 硬超时只说明「没在线上跑完」，不说明源失效。任何被超时终止的源，必须再跑一次 90 秒复核（`--hard 90 --tag=-90s`），按结果分为「慢源（可用/部分可用）」与「真挂（90 秒仍未完成）」，复核前不得写入「不纳入」或删除。

本次 30 秒全量实测的 10 条 js 挂起源，90 秒复核后出现三个反例，正是调整 js 超时线的依据：

| 源 | 30 秒线结果 | 90 秒复核结果 | 结论 |
|---|---|---|---|
| 金鹰（jinying） | 30.15s 被终止 | 70.75s 完成，可用 | 30 秒误判，源本身可用 |
| 红牛（hongniu） | 30.2s 被终止 | 71.96s 完成，可用 | 30 秒误判，源本身可用 |
| 牛牛（niuniu） | 30.2s 被终止 | 46.29s 完成，部分可用 | 30 秒误判，需降档保留 |

同一轮里另有 6 条 js 在 90 秒仍未完成（飘零、虎牙、索尼、极速、最大、魔都），这 6 条才进入「真挂」待复测；即便如此也只登记「暂不可测」，不直接判死。

### 2.7 能力类型判定（四型分类，2026-11-08 新增）

**红线：分类为空 ≠ 失败。** 首页无分类、分类下无片，只能证明「这条源没有浏览入口」，不能证明源失效。凡因分类为空被判失败的，必须补测「直接搜索」路径，再下结论。

四型定义与处置：

| 型 | 判据（缺一不可） | 处置 |
|---|---|---|
| 全功能型 | 分类有片 + 详情可进 + 播放取到地址 + 搜索有结果 | 正常入包，排在全部源之前 |
| 仅搜索型 | 分类为空或无分类，但固定关键词搜索命中 ≥ 1、详情可进、播放取到地址 | 入包；名称末尾（内容符号之后）加 `🔎`；整组排到中后段 |
| 仅分类型 | 分类有片且可播，但固定关键词搜索 0 结果 | 入包（`searchable` 写 `0`），排在仅搜索型之前 |
| 无入口型 | 分类与搜索都取不到结果，或装载/详情/播放任一环节失败 | 判失败，进观察池，不得留在成品占位 |

判定步骤（每条源都走）：

1. 客户端内跑分类四段：`homeContent` → `categoryContent` → `detailContent` → `playerContent` → 实拉字节。
2. 同一源再跑搜索：按线路取固定关键词池（std `庆余年,流浪地球,哪吒`；kids `小猪佩奇,汪汪队,熊出没`；elders `戏曲,西游记,三国演义`），`quick=false` 与 `quick=true` 各试一次；命中第一条即进详情、起播、实拉字节。
3. 搜索成功行不带 `|ms=`，执行器必须按 `|n=` 识别，不得按 `|ms=` 过滤（否则搜索结果会被当成无输出丢弃）。
4. 分类结论与搜索结论并列记录，不得用「搜索无结果」覆盖分类结论，也不得用「分类为空」覆盖搜索结论。
5. 归类只看上表；一条源只归一层，归类依据必须写入证据列。

命名与排序：

- 仅搜索型名称 = 内容符号 + 原标题 + 速度符号 + `🔎`（例：`🎬飘零🔎`、`♻️🎬金鹰🔎`）；`🔎` 只在末尾，不得前置、不得改写内容符号（TVB-NAM-024）。
- 三型排序：全功能型 → 仅分类型 → 仅搜索型；同型内仍按播放速度档（流畅 → 一般 → 卡 → 无法测）。
- 用户说明固定写一句：带 `🔎` 的源没有分类页，直接搜索使用。

环境失败与源失败必须分开：装载失败若由测试环境造成（如 js 脚本未随包、模拟器缺 ARM native、客户端无 Python 引擎），结论写环境原因，不写「源不可用」。

### 2.8 主客户端与兼容校验（2026-11-08 新增）

**以谁为准**：主客户端 = 影视仓（包名 `com.huawei.himovceie`，CatVod 契约）；TVBox 为兼容客户端。

| 情形 | 判定 | 处置 |
|---|---|---|
| 两客户端都显示分类、都能进片 | 通过 | 正常入包 |
| 影视仓正常、TVBox 异常 | 兼容回归 | 先修源保住影视仓，再定位 TVBox 差异 |
| TVBox 正常、影视仓无分类 | **格式不兼容**（不是「无分类」、不是「不可用」） | 必须改源适配影视仓；修不动才判不可用，并列出尝试过的改法 |
| 两边都无分类且搜索也空 | 无入口型 | 进观察池 |

怎么验证（每条 js 源两遍）：

```powershell
node 工具\完整测试\js-runner.mjs --api <脚本路径> --skey <key> --catvod 1 --timeout 20000
node 工具\完整测试\js-runner.mjs --api <脚本路径> --skey <key> --timeout 20000
```

- `--catvod 1` 走 `homeContent/categoryContent/detailContent/searchContent/playerContent`，其中 `detailContent` 传数组，模拟影视仓。
- 不带该参数走 `home/homeVod/category/detail/play/search`，模拟 TVBox。
- 两次都必须 `classCount ≥ 1` 且分类下 ≥1 条；影视仓侧以 `homeContent` 的分类数为准。
- 影视仓 APK 仅含 arm64-v8a，x86 AVD 无法安装（QEMU2 不支持 arm64 宿主）；不能实机时以 `--catvod 1` 结果 + TVBox 真机探针双向留证，不得默认通过（TVB-PRC-010）。

怎么记录：

1. 每条源写「分类数 / 首分类条目数 / 首片地址」三项，影视仓与 TVBox 各一行。
2. 无法实机的写「替代验证：`--catvod 1` 分类 N 条」，并写明为什么无法实机。
3. 兼容冲突按 `TVB-PRC-008` 记「格式不兼容」，并在 `记录/<日期>/tvbox/冲突处置-<包id>.md` 留痕；不得在观察池记成「不可用」。

## 6. 坑位库（TVBox 专属）

### 6.1 布尔 `false` 被吞

- 现象：`"searchable": false` 后仍参与搜索。
- 根因：客户端按整数解析，布尔被吞后回落默认可搜索。
- 正确做法：写数字 `0/1`，写完逐条核对。
- 证据来源：`safeJsonInt` 实现与实机。

### 6.2 `;md5;` 不是真实 URL

- 现象：直接 GET 404。
- 根因：后缀由客户端解析。
- 正确做法：截断后再请求或只校验文件本体。
- 证据来源：`JarLoader` 解析。

### 6.3 中文目录百分号编码 + `./`

- 现象：线路配置取不到，站点全空。
- 根因：`clan://` 不认 URL 编码与相对路径。
- 正确做法：`clan://localhost/<包名>/<中文目录>/api.json`。
- 证据来源：本地包加载失败记录。

### 6.4 jsDelivr 对 jar 403

- 现象：jsDelivr 下 jar 加载失败。
- 根因：CDN 拒绝二进制大文件。
- 正确做法：jsDelivr 只发 JSON，jar 走 raw。
- 证据来源：实机日志。

### 6.5 raw CDN 缓存

- 现象：推完 `main` 仍返回上一版。
- 根因：raw 缓存未刷新。
- 正确做法：用 tag 路径校验。
- 证据来源：发布校验记录。

### 6.6 包装层回归

- 现象：包装版无分类，直连版正常。
- 根因：`type:3` + JS 的导入契约或解析错误。
- 正确做法：包装与直连分别跑 `home`/`category`，先修包装再判站点。
- 证据来源：21 条包装源 `import {req} from 'cat.js'` 事故。

### 6.7 接口 200 但空壳

- 现象：`ac=list` 200 且 `class` 为空。
- 根因：空壳接口用 200 掩盖无数据。
- 正确做法：分类非空 + 分类有片 + 详情可解析 + 播放可拉流，逐级验。
- 证据来源：TVBox 151 站体检。

### 6.8 四段全过也可能卡

- 现象：四段全通但播放卡。
- 根因：源站 CDN 吞吐只有码率 0.4–0.8 倍。
- 正确做法：单列「卡」档，不与流畅混排，写明源侧不可修。
- 证据来源：小猫影视 1.3.0 同类现象；TVBox 播放层同样按此判。

### 6.9 直播 HTML 错误页

- 现象：200 但无频道。
- 根因：返回 HTML 登录页/错误页。
- 正确做法：前 8 KB 首行必须 `#EXTM3U`。
- 证据来源：直播探活记录。

### 6.10 `extra.category` 未验证

- 现象：分类不显示或只显示一个。
- 根因：字段语义未真机证实。
- 正确做法：TVBox 不使用该字段；分类走客户端原生 `ac=list`。
- 证据来源：`参考资料/小猫影视/docs/create_source.md` 与 TVBox 配置格式差异。
