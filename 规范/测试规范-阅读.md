## 1. 测试对象与范围

### 1.1 书源（`bookSource`）

| 项 | 规定 |
| --- | --- |
| 被测对象 | 入包候选的全部 `bookSource`（原件 + 网上补充源），逐条测，不抽样 |
| 测什么 | 搜索 → 详情 → 目录 → 正文 四层；每层必须拿到**实质内容**，不是只看 HTTP 200 |
| 不测什么 | 发现（`exploreUrl`）不计入可用性，只作为搜索不可用时的补充观察项；`type=1/2/3`（音频/图片/文件）正文段改测资源可访问（见 §2.4） |
| 数据基线 | 客户端基线版本见阅读源规范 §2.1；规则语义以其为准 |

### 1.2 订阅源（`rssSource`）

| 项 | 规定 |
| --- | --- |
| 被测对象 | 待入包的全部 `rssSource`（普通 + 成人分开统计） |
| 测什么 | 按 `sortUrl` 拆出的**每个分类**逐一探活：能解析出条目 → 标题非空 → 首条链接能打开（HTTP <400）→ 最近有更新 |
| 不测什么 | 不把「首页 200」当可用；不抽样，分类级全测 |
| 特别约定 | `ruleArticles` 为空时走 `RssParserDefault`（只认 `<item>`，不认 Atom `<entry>`），此类源必须在报告里注明「Atom 不支持」而不是判死 |

### 1.3 一律不做的事

- 不复用上一轮结论；上一轮报告只作对照。
- 不以「字段齐全」「JSON 能解析」当作可用性证据（见 §6 坑位库）。
- 不改原件；测试只读原件，成品另写新目录，原件备份保留。

## 2. 判据（可量化）

### 2.1 结论三态（书源、订阅源同用）

| 状态 | 定义 | 处置 |
| --- | --- | --- |
| 确认可用 | 规定层级**全部通过**，每层都有实质产出与证据 | 进成品 |
| 仍有阻塞 | 卡点属于 JS 执行 / 验证码或签名 / 登录 / 反爬 / 规则不匹配 / 站点改版，且已按 §3 手段试过 | **不进成品**，单列阻塞清单；进观察池（§4.4） |
| 确认不可用 | 任一层**确定失败**且能给出失败证据 | 不进成品；删除并留记录 |

禁止把「无法判定」作为最终结论；无法判定必须归入上面三态之一，并写清卡在第几层。

### 2.2 书源四层通过条件

| 层 | 通过条件（全部满足） | 必须留的证据 |
| --- | --- | --- |
| 搜索 | HTTP 2xx；前 10 条中 ≥1 条 `name`/`author`/`intro` 含目标关键词；单次耗时 ≤15s（8–15s 记「慢」，排成品末尾） | HTTP 状态、返回条数、相关条数、命中样例、耗时 ms、所用 `searchUrl`（渲染后） |
| 详情 | 能进详情页；**书名非空**且**简介非空且 ≥10 个汉字、非广告**（简介规则为空时允许用 `meta description` 兜底，须注明「meta 兜底」） | 命中的选择器/JSONPath、书名与简介前 80 字、HTTP 状态 |
| 目录 | 有效章节 ≥1；章节名不是「首页/排行/登录/上一页」等导航词；链接可绝对化 | 命中的选择器/JSONPath、章节数、前 3 章标题、HTTP 状态 |
| 正文 | 正文 ≥300 个连续汉字；非广告页/目录页/防盗提示页（广告提示词命中 <3 处，或命中但正文 ≥800 字） | 命中的选择器/JSONPath、正文前 80 字、汉字数、HTTP 状态 |

- 搜索关键词集固定为 12 个（清单见 §3.1，测试脚本与本章同一份，改动须同步两处），覆盖书名/作者/泛指/长尾；**每条源至少用主关键词跑 3 次**，写成功率（`3/3` 才算稳定，`1/3`、`2/3` 记「时通时不通」）。
- 详情判据比阅读源规范 §11.1 的 RBS-PRB-002 更严：旧标准「name 与 author 至少一个」不再使用；本规范要求**书名 + 非空简介**，依据见 §6 坑位库第 4 条。

### 2.3 订阅源通过条件（分类级）

| 项 | 通过条件 | 证据 |
| --- | --- | --- |
| 条目 | 分类链接能解析出 ≥1 条（规则或标准 RSS） | 条目数、解析方式（规则/`<item>`/`<entry>`） |
| 标题 | 非空标题 ≥1 条；标题全空判「规则不匹配」 | 首条标题前 40 字 |
| 链接 | 首条条目链接实测 HTTP <400 | HTTP 状态；401/403/429 记「疑似反爬」而非站点已死 |
| 更新时效 | 最近一条 `pubDate` 在 30 天内；取不到日期则记「无日期，无法判时效」 | 最近更新日期 |
| 分类级 | 一个源只要有 ≥1 个分类四门全过即「确认可用」；全部分类失败才「确认不可用」 | 可用分类数/总分类数 |

订阅源四档结论沿用阅读源规范 §17.7；本规范只加严「链接必须实测打开」这一条。

### 2.4 非文本类型

| 类型 | 替代判据 |
| --- | --- |
| 音频 `type=1` | 首章资源 URL 2xx 且 `Content-Type: audio/*`，或直链 `.mp3/.m4a/.aac` |
| 图片 `type=2` | `content` 解析出 ≥1 个图片 URL，首图 2xx 且 `Content-Type: image/*` |
| 文件 `type=3` | `downloadUrls` 返回 ≥1 个可访问链接（HEAD/GET 2xx） |

### 2.5 耗时阈值

| 指标 | 阈值 | 处置 |
| --- | --- | --- |
| 搜索单次 | ≤8s 正常；8–15s 记「慢」；>15s 记「超慢」 | 慢/超慢仍可进包但排末尾；>30s 判挂起 |
| 详情 + 目录 + 正文链 | ≤45s | 超时判挂起 |
| 单源累计 | ≤90s | 超时无条件判挂起 |
| 整批 | 记录总耗时与请求数 | 写进说明文件 |

### 2.6 成人识别三层判据

任一层命中即标记为成人；只命中弱词不算识别到，必须由强词、分类名或显式内容词支撑。

| 层 | 取数方式 | 判定要点 |
| --- | --- | --- |
| 词表层 | 源名、源分组、域名 | 命中 `18/po18/popo/禁漫/里番/无遮/成人/伦理/海棠/废文/秀人/尤物/写真` 等强词；`18/nh/acg/同人/韩漫/耽美/豆腐/美女/图集/丝袜` 等只作弱信号，需配合其他层 |
| 分类探针层 | 源的 `exploreUrl` / `sortUrl` 声明分类 + 站点实际分类锚文本（href 含 category/list/sort/tag） | 分类名直接命中 `乱伦/成人/情色/伦理/R18/18+/无码/里番/H漫/人妻/熟女` 等即成人；`福利/写真/同人/韩漫/激情` 为弱分类，需两项以上 |
| 内容特征层 | 首页或搜索结果的书名、标签（标题与 meta 不参与） | 显式词 `乱伦/肉文/里番/无遮/禁漫/H漫/福利番/性奴/母子/父女/淫乱/高H/H文/淫` 出现 ≥2 种，或 1 种 + 2 个以上模糊词；`福利番外` 不算；`举报色情/成人教育/未成年` 等站务与无关词必须排除 |

- 词表落盘位置为本机非公开目录（开发侧维护，不随公开仓发布）；词表改动必须升版本并写备注。
- 判定结果分 `成人 / 疑似 / 非成人` 三档；只有 `成人` 进成人文件，`疑似` 留在普通并记入清单，下一轮复测可升级。
- 有效性必须实测：抽 30–50 条正反例人工核对，报告精确率、召回率与核对依据；召回率低说明判据不足，须补词或补层后再测。

## 3. 执行步骤

### 3.1 关键词集

固定 12 词（脚本与本节保持同一份清单）：`斗破苍穹 / 诡秘之主 / 凡人修仙传 / 剑来 / 赘婿 / 忘语 / 猫腻 / 辰东 / 重生 / 悬疑 / 无限流 小说 / 都市 异能 完本`。主关键词固定第 1 个；测速与成功率用主关键词，覆盖率用全量 12 词（大跑时可选，但最终报告必须写用了几个词）。

### 3.2 编码

同一响应依次尝试：`meta charset` 声明 → `GB18030` → `UTF-8`。任一解码能解析出条目即通过，证据里写实际编码（`改按 GBK 解码后取到条目`）。

### 3.3 JS 规则

- `searchUrl` 为 `@js:` / `<js>`，或模板中混入 `{{...}}` JS 表达式：一律用本机 Node 沙箱执行（开发侧脚本 `jsexec.py` 与 `_jsexec_runner.js`，不随公开仓发布，仅登记文件名），执行前**先注入 `jsLib` 与对应 `ruleXxx.init`**。
- 详情/目录/正文规则含 JS：同样执行，`result` 按 Legado 语义传值（JSON 响应给对象，HTML 给文本），并注入 `ruleBookInfo/ruleToc/ruleContent` 的 `init`。
- 沙箱提供 `java.ajax/ajaxGet/ajaxPost/base64Encode/md5Encode/md5Encode16/put/get`、`cookie`、`org.jsoup.Jsoup.parse` 子集；脚本 9s、子进程 12s 上限。
- 只有沙箱**执行报错**（带 Node 报错原文）才允许记「仍有阻塞 · JS执行」，不许因为「规则里含 JS」直接判死。

### 3.4 请求头

每个搜索请求依次尝试两组头：
1. 默认移动端 UA + `Accept-Language: zh-CN`；
2. 桌面 UA + `Referer: bookSourceUrl`（源自带 `header` 始终透传）。

403/429 记「疑似反爬」，加随机间隔后最多重试 1 次；仍 403/429 记「仍有阻塞 · 反爬」，不记「站点已死」。

### 3.5 超时、重试、并发、限速

| 项 | 数值 |
| --- | --- |
| 单请求超时 | 10s（可调，默认 10，最大 12） |
| 非 2xx 重试 | 1 次（仅非 2xx；超时不重试） |
| 全局请求间隔 | 0.2s + 每次 0–0.12s 随机抖动 |
| 并发 | 10 个源（每源独立线程） |
| 搜索硬超时 | 30s（含 3 次复测） |
| 正文链硬超时 | 45s（详情+目录+正文） |
| 单源看门狗 | 90s（无条件判挂起） |

### 3.6 挂起隔离（硬要求）

- 每条源独立线程执行，到硬超时立即放弃该源、不阻塞后续源；不重试第二次以外的次数。
- 单源累计 >90s 判「挂起」；**首轮挂起后必须复跑第二轮**：
  - 两轮均挂起 → 删除，进《挂起源清单》：源名、卡在第几步（URL 构造/连接/读取/解析）、最长耗时 ms、是否影响批处理；
  - 只有首轮超时、第二轮正常 → 不算挂起，记「间歇」，进观察池（§4.4），不删。
- 整批设全局看门狗：任何一个源占用超过 90s 立即放弃，记录到挂起源清单。

### 3.7 多轮取多数

- 搜索层固定跑 3 次写成功率；
- 阈值型判定（相关条数、正文长度）以 3 次中 ≥2 次通过为准，不拿单次结果定生死；
- 详情/目录/正文各跑 1 次，异常时允许换第 2 个搜索结果再验一次（计入证据）。

### 3.8 客户端方式误杀复核

判定为「确认不可用」之前，必须用接近真实客户端的方式独立复核一遍，不得复用原判解析逻辑：

- 请求头：移动端 Chrome UA；`Referer` 取源站首页；能取到 Cookie 就带上，用同一 Session 贯穿搜索→详情→目录→正文；
- 跳转与方法：跟随 301/302；`searchUrl` 是 POST 的必须按 POST 发（表单/JSON 按源声明）；
- 编码：GBK 站点把关键词按 GB18030 编码后再拼 URL；
- 关键词：至少 3 组（具体书名、作者名、泛词），任一命中即继续往下测；
- JS：规则在 Node 沙箱真跑，缺 API 先补（优先 `java.*`、`cookie`、`source`、`baseUrl`、`cache`），跑不通要写明缺哪个 API，不许直接判死；
- 抽样：从「确认不可用」池按固定种子抽 30 条复核，统计误杀率；误杀率 >10% 必须回退重判全部条目，并在报告写明回退依据；
- 判死原因必须归入：站点已死 / 规则不匹配 / 反爬 / 需登录 / JS 缺 API / 关键词不当。

### 3.9 基线字段对照（判死前置）

2026-11-12 复盘：`⑱ 秘密入口`、`⑱ YY舞曲网` 不是站点失效，而是修复时把字段语义改坏；`⑱ 爱看买家秀`、`⑱ 其他` 被单轮空白误判死。自此判死前必须完成以下步骤：

1. **先取基线**：按优先级取用户上传的初始版 → 仓内 HEAD 成品 → 历史 tag；三者都取不到时，才允许用「删除前最后一次提交」作基线，并在结论注明。
2. **字段级对照**：逐项比对 `sourceUrl`、`singleUrl`、`loadWithBaseUrl`、`sortUrl`、`searchUrl`、`header`、`type`、`enabled`、`rule*`。当前值与基线不一致的，**先回退基线值复测一次**；只有基线值也失败，才可进入判死流程。
3. **单轮空白不判死**：同一参数至少 2 次客户端实测（间隔 ≥10 分钟），并配合双路径（系统 DNS / DoH、PC 直连 UA）交叉验证。
4. **「间歇」与「参数错」分型**：
   - **间歇**：同参数多次结果不一致，或 PC 可达而客户端超时，或 UA/节点敏感，或 DNS 双路径不一致 → 判「间歇」，保留并进观察池，不得删除。
   - **参数错**：同参数稳定失败，且回退基线仍失败；或命中结构错误（`singleUrl=false` 且规则全空、`##` 绑定被拆、模板变量残留）→ 判「参数错」，按规范修复或删除。
5. **留痕**：结论必须写「基线值 → 当前值 → 实测时间/现象 → 判定」四段，缺任一段的判定不成立。

## 4. 验收门禁

### 4.1 什么不进成品

| 情形 | 处置 |
| --- | --- |
| 任一列为「仍有阻塞」 | 不进成品；单列《仍有阻塞.csv》+ 已尝试手段 |
| 任一列为「确认不可用」 | 不进成品；进《不可用.csv》并删除，保留证据 |
| 「挂起」两轮 | 不进成品；进《挂起源清单.csv》并删除 |
| 搜索 3 次成功率 <3/3 且非全挂（间歇） | 进成品，名称加 ` ♻️` 后缀并排同类末尾；观察池状态记「已入包·间歇」 |
| 成人内容（三层判定命中 `成人`） | 只进 `书源_成人.json` / `订阅源_成人.json`，不公开；`疑似` 留普通并单独列清单 |

### 4.2 成人分流落点

- 书源：`书源_普通.json`、`书源_成人.json`；
- 订阅源：`订阅源_普通.json`、`订阅源_成人.json`；
- 普通文件内夹带的成人条目必须整条移出到成人文件，不在普通文件里保留；
- 判定按 §2.6 三层执行，词表在本机非公开目录维护；成人文件的每一条都要在清单里写清「命中层 + 证据」；
- 成人文件只收 `成人` 判定；不可用源即使判定为成人，也只进清单、不进文件。

### 4.3 条数与体积上限

| 项 | 上限/下限 | 说明 |
| --- | --- | --- |
| 书源单文件 | ≤10 MB | 超过必须拆分或删减 |
| 单条书源 JSON | ≤200 KB | 超过须注明原因（多为内嵌 `jsLib`） |
| 书源成品条数 | 不设硬下限 | 低于 40 条如实报，不许把阻塞项塞回凑数 |
| 订阅源单文件 | ≤5 MB | — |
| 单条订阅源 | ≤100 KB | — |

### 4.4 观察池（间歇源专用，禁止直接删）

固定位置：`tvboxSL\记录\观察池\reading\`

## 6. 坑位库

| 编号 | 现象 | 根因 | 正确做法 | 依据 |
| --- | --- | --- | --- | --- |
| RBS-KEN-001 | 规则里写了 `##替换##` 却不生效，也不报错 | `##` 只能 2–4 段；写成 1 段或 5 段会被静默忽略 | 固定写 2 段（`##正则##替换`）或 3 段（含 `##正则##替换##` 分组）；测试时用样例文本验证替换结果 | 客户端规则解析 |
| RBS-KEN-002 | `canReName: false` 仍能改名 | 该字段是**字符串**；写成布尔 `false` 会被当字符串 `"false"`，等于允许改名 | 要禁止改名写 `"false"`（带引号）且确认客户端读取为字符串 | 阅读源规范 §4.2 |
| RBS-KEN-003 | 条目字段齐全、JSON 能解析，但实际搜不到书 | 「字段齐全」只说明格式合格，不等于站点可用；可用性看搜索与正文 | 可用性一律用 §2.2 四层判据；不要把打包规范（RBS-PRC-028~039）当可用性判据 | §13.2 与 §11.1 的职责分离 |
| RBS-KEN-004 | HTTP 200 就判可用，结果正文是广告页/登录页 | 状态码只说明连接成功；空壳页、登录页、防盗页、目录页都可能是 200 | 按内容特征判定：关键词是否出现在结果里、正文汉字数、广告/防盗词命中数、登录词命中；证据写响应片段 | §2.2、§11.3 占位词 |
| RBS-KEN-005 | 规则含 JS 直接判死，好源被误杀 | 静态解析器不执行 JS，旧口径「无法判定」被当成死源 | 必须真的在本机执行一遍（Node/Rhino），注入 `jsLib` 与 `init`；只有执行报错才记「仍有阻塞 · JS执行」 | §3.3 |
| RBS-KEN-006 | 分类数 40、标题 2–10 字这类阈值把好源判死 | 真实站点高频命中阈值边界，阈值过严等于误杀 | 阈值只用于**排序与提示**，不作为删除条件；删除只认四层确定失败 | §2.5、RBS-PRB-016 |
| RBS-KEN-007 | 单源卡住拖住整批 | 无硬超时、无隔离，阻塞线程 | 每源独立线程 + 30s/45s/90s 三级硬超时 + 两轮挂起判定 | §3.6 |
| RBS-KEN-008 | 429/403 被记成「站点已死」 | 把限流当死亡 | 401/403/429/503 一律记「疑似反爬」，加随机间隔重试 1 次；仍失败记「仍有阻塞 · 反爬」 | §3.4 |
| RBS-KEN-009 | 一次搜索结果不理想就删源 | 单次结果受关键词、时段、站点负载影响 | 主关键词跑 3 次取多数；详情/目录/正文允许换第 2 本书复验 | §3.7、RBS-PRB-012 |
| RBS-KEN-010 | 编码乱码导致「选择器为空」 | 站点是 GBK，按 UTF-8 解码成乱码 | 依次试 meta 声明、GB18030、UTF-8；解码成功再解析 | §3.2 |
| RBS-KEN-011 | 搜索有结果、目录条数正常，正文却报 `ContentEmptyException`；同一规则在桌面抓页时正文完好，客户端必空 | 站点按 UA 分模板（桌面/移动各一套 DOM），两套正文容器无共同 class。客户端 UA 固定命中其中一套，规则若按另一套模板写，选择器恒为空。本质是「模板漂移」，不是选择器语法错、不是编码、不是反爬 | 先用两组 UA（客户端默认 UA、桌面 UA）各抓一次正文页，比对正文容器是否一致；不一致就改 js 规则按顺序回退尝试（如 `div.chapter` → `#content article` → `#content`），按子节点遍历取文本，不要依赖单一路径；预删 `font`/`script` 并剔除广告占位行。判据以客户端内解析结果为准，不以桌面 `urllib` 抓页为准 | 2026-11-09 `⑱ 靠谱小说`（kptxt.com）正文修复 |
| RBS-KEN-012 | 写 `div.chapter, article@textNodes` 这类逗号选择器，规则静默失效或报空 | Legado 规则串里的 `,` 是**规则/选项分隔符**，不是 CSS 选择器逗号，逗号写法不会按 CSS 语义合并多个选择器 | 需要覆盖多个候选容器时改用 js 规则显式回退，或拆成多条规则分别验证后取有效的那个；不要用逗号合并选择器 | 2026-11-09 `⑱ 靠谱小说` 复验 |
| RBS-KEN-013 | 订阅源在客户端打开是全白/只有顶栏，PC 抓首页正常；报 `Failed to load` 或 `SocketTimeoutException` | 把 `singleUrl=true` 改成了 `false`。`true` 表示整条源交给 WebView 渲染入口页，入口页里的跳转/挑战脚本只有在该模式执行；改 `false` 后走列表解析链路，而该源没有 `sortUrl`/列表规则，必然空白。另一种同源错误是 `singleUrl=false` 且 `sortUrl`、`rule*` 全空（结构性空白） | 先与基线对照 `singleUrl`；基线为 `true` 的不得改 `false`，逐字恢复原值再测。判死前跑门禁 C1（`singleUrl=false` 且规则全空）；确属 WebView 型源（入口页/聚合导航/单页图集）保持 `singleUrl=true`、不加列表规则 | 2026-11-12 `⑱ 秘密入口`、`⑱ 爱看买家秀`、`⑱ 其他` 三例复盘 |
| RBS-KEN-014 | 恢复/修改订阅源后客户端报 `Failed to load`，或列表正常但点进去报 `ReferenceError`/空正文 | 删掉了 `sourceUrl` 末尾的 `##` 后缀（或其后的线路/Referer 标记）。`header` 里常用 `source.getKey().match(/([^#]+)#/)[1]` 取基址，后缀一删，正则不匹配，header 取空或抛错；同理，后缀还可能是站点识别 Referer/线路的唯一依据（如只认 `www` 域） | `##` 后缀及其后文本一律原样保留；确需改 Referer 时改 header 里的取值表达式（如 `.replace("//m.","//www.")`），不要动 `sourceUrl` 后缀。改完必须同时验证分类页、详情页、正文/播放页 | 2026-11-12 `⑱ YY舞曲网` 复盘（删 `##` → `Failed to load`；恢复后 DPlayer 出画面） |
