## 1. 测试对象与范围

### 1.1 对象

| 项 | 内容 |
|---|---|

## 2. 判据

### 2.1 结构层

| 项 | 通过线 |
|---|---|
| JSON | 可解析；顶层 `sites`/`data`/`lives` 存在 |
| 站点必填 | `id` / `name` / `api` / `type` 齐全；`id` 唯一且小写 |
| `type` | maccms 固定 `0`；JS 固定 `1` |
| `extra.category` | 若存在必须是合法 JSON 字符串；本版一律不写（见 2.6） |
| 成人 | 公开文件不得出现成人主体源；成人源只在私有域 |

### 2.2 功能层（四段，逐段验到真拿到东西）

| 段 | 通过线 | 失败示例 |
|---|---|---|
| 1 分类可解析 | `class` 非空；`type_id`/`type_name` 齐全；名称不含 `�` 与连续拉丁乱码 | 200 但 `class` 为空 |
| 2 分类下有片 | ≥ 2 个分类各取到 ≥ 1 条带 `vod_id`+`vod_name` | 分类有 id 但列表空 |
| 3 详情完整 | `vod_play_url` 非空，含 ≥ 1 个可解析「集名$地址」 | 只有片名无播放地址 |
| 4 播放可拉流 | 首地址前 100 KB 为 `#EXTM3U`/TS/`ftyp`/FLV，或 `Content-Type: video/*` | 200 但返回 HTML/0 字节 |

单轮四段任一不过即该轮记「挂」，写明卡在第几段；最终结论按 2.4 多轮取多数，不得用单轮失败直接判死。单条片源无播放地址时允许换第 2、3 条片重试，仍无才判第 3 段失败。

### 2.3 播放层

| 指标 | 采样 | 通过线 |
|---|---|---|
| 首片延迟 | m3u8 首分片首字节；mp4 前 5 MB 首字节 | ≤ 3000 ms |
| 实测速率 | 首分片/前 5 MB 下载速率 | 记录值 |
| 码率 | 主清单 `BANDWIDTH`，否则分片字节×8÷`EXTINF` | 记录值 |
| 10 秒断流 | 10 秒窗口继续拉后续分片，异常计 1 次 | ≤ 1 次 |
| 判档 | 速率 ≥ 码率×2 → 流畅；≥×1.5 → 一般；<×1.5 或首片 >3s 或断流 ≥2 → 卡 | 卡单独成组 |

多条播放线路时逐条测第一集，取最好一条作为该源判档，快的排前。

### 2.4 稳定性层

| 项 | 值 |
|---|---|
| 轮数 | 3 轮（上一版 21 条间歇源同样 3 轮） |
| 轮间隔 | ≥ 60 秒 |
| 超时 | 首轮 10 秒，失败放宽 20 秒；详情/播放 20 秒 |
| 重试 | 单端点 2 次；GET 失败后 POST 回退 |
| 挂起线 | 分类 30 秒、详情+播放 45 秒；累计 90 秒看门狗强杀 |
| 判定 | 3 轮全通 = 稳定；1–2 轮 = 间歇；0 轮 = 不可用 |

### 2.5 收录与排序

- 只收 3 轮全通且四段全过的源。
- 排序：先按判档（流畅 → 一般 → 卡），同档按接口速度档位；卡源不与流畅源混排。
- 名称保留「档位｜站点名」，判档写在 README 与体检表，不改站点 `key`/`api`/`type`。
- 当前 19 条中 9 条判「卡」，是否降档或转备用由用户裁决；**裁决前不改 `config.json` 排序**。

### 2.6 `extra.category` 取舍

- 参考文档 `参考资料/小猫影视/docs/create_source.md` 对 maccms 的 `category` 描述为「分类 ID 或名称（用于筛选特定分类）」，示例又出现 `"category": "[]"` 注释「静态分类」，语义存在歧义，且未在真机证实。
- 本版**不写 `extra.category`**：分类由客户端读取上游 `ac=list` 原生 `class`。
- 代价（必须写进发布说明）：成人分类按上游原样出现，不再置后、不再加 `（成人）` 后缀；曝光控制只能靠「成人主体源进私有域」。
- 待真机证实该字段接受数组后，才允许恢复置后与后缀。

## 6. 坑位库（小猫影视专属）

### 6.1 接口 200 但分类为空

- 现象：`ac=list` 返回 200，`class` 为空。
- 根因：空壳接口用 200 掩盖无数据。
- 正确做法：分类非空 + 分类有片 + 详情可解析 + 播放可拉流，逐段验。
- 证据来源：1.2.0 的 36 条里有 3 条此类源。

### 6.2 详情只有名字没有播放地址

- 现象：搜索/详情正常，点开无地址。
- 根因：上游 `vod_play_url` 为空或格式非常规。
- 正确做法：第 3 段判失败；允许换 2–3 条片重试，仍无才判死。
- 证据来源：1.3.0 艾旦影视、爱奇艺资源。

### 6.3 地址需会员鉴权

- 现象：首地址 403 或返回登录页。
- 根因：源站 CDN 鉴权。
- 正确做法：判第 4 段失败，写明「源侧无法修复」，不进成品。
- 证据来源：1.3.0 西瓜、鸭鸭、爱奇艺。

### 6.4 四段全过但播放卡

- 现象：四段全通，实测速率只有码率的 0.4–0.8 倍。
- 根因：源站 CDN 限速。
- 正确做法：单列「卡」档，不与流畅源混排，写明源侧不可修复。
- 证据来源：1.3.0 的 360（1047–1081 / 2525）、ikun（3810 / 4824）、猫眼（545 / 1000）、非凡（434 / 800）。

### 6.5 直播返回 HTML 错误页

- 现象：200 但无频道。
- 根因：错误页/登录页伪装 200。
- 正确做法：前 8 KB 首行必须 `#EXTM3U`。
- 证据来源：直播探活。

### 6.6 `extra.category` 未验证

- 现象：写入数组后不确定是否渲染分类。
- 根因：官方文档语义歧义。
- 正确做法：不依赖该字段；分类走上游 `ac=list`。
- 证据来源：`参考资料/小猫影视/docs/create_source.md`。

### 6.7 移除 `extra.category` 的副作用

- 现象：成人分类不再置后、无后缀。
- 根因：置后与后缀依赖该字段。
- 正确做法：在规范与发布说明写明代价；曝光只靠私有域分流；待真机验证后恢复。
- 证据来源：1.3.0 配置变更。

### 6.8 重复后端

- 现象：两条源分类表与首集 id 完全一致。
- 根因：同一后端多域名。
- 正确做法：保留一条，记录对比证据（分类数、首集 id）。
- 证据来源：1.2.0 的 `cj_ffzyapi_com`、`ffzy5_tv`。

### 6.9 超时被误判为失效

- 现象：单轮 ReadTimeout 就判死。
- 根因：TLS 抖动与源站限流。
- 正确做法：10 秒→20 秒、重试 2 次、3 轮取多数；单轮失败入观察池。
- 证据来源：1.3.0 的 14 条间歇源。
