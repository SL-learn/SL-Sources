## 1. 定位与范围

### 1.1 定位

| 项 | 内容 |
|---|---|
| 是什么 | 个人自用的影视/直播源仓库；包含配置、脚本、jar 与探活记录，可本地安装，也可在线直拉 |
| 给谁用 | 仓库所有者本人及其家庭设备；不做公开运营、不做付费分发 |
| 部署形态 | 本地目录（`/sdcard/TVBox/<包id>/`）+ 在线直链（GitHub / Gitee，jsDelivr 仅加速） |
| 内容形态 | 一个包内含多条线路（综合 / 少儿 / 长辈），在客户端「线路选择」里切换 |

### 1.2 范围外（明确不做）

| 编号 | 不做的事 |
|---|---|
| R-SCP-01 | 不编写新的爬虫实现，不逆向、不破解第三方付费或鉴权接口 |
| R-SCP-02 | 不聚合、不链接任何成人内容；不保留任何成人站点，即使来源包已标注 |
| R-SCP-03 | 不收录网盘、盘搜、云盘转存类站点 |
| R-SCP-04 | 不伪造上游数据、不伪造探活结论、不把「无法判定」写成「可用」 |
| R-SCP-05 | 不做商业售卖、引流、代充、二次分发收费 |

## 2. 客户端事实基线（TVBox）

本章只陈述**源码可证**的行为，作为后续所有规则的前提；不再在其它章节重复。

| 编号 | 事实 | 依据 |
|---|---|---|
| R-CLI-01 | `type` 取值：`0`=XML CMS，`1`=JSON CMS，`3`=爬虫（jar/js/py），`4`=remote，`-1`=内置 `push_agent` | `ApiConfig.java` 解析分支 |
| R-CLI-02 | `type:3` 的加载器按 `api` 后缀分流：`.js`/`.js?` → JsLoader；含 `.py` → pyLoader；其余 → JarLoader（**不校验扩展名**，`.jpg`/`.png` 伪装的 jar 可加载） | `ApiConfig.java:1456-1470` |
| R-CLI-03 | jar 加载：`DexClassLoader`；类名必须在 `com.github.catvod.spider.` 下；`api` 含 `csp_` 时取后半段；`;md5;` 之后为校验值 | `JarLoader.java` |
| R-CLI-04 | jar 缓存文件为 `cacheDir/jar/<md5(jar地址)>.jar`。**带 md5**：本地文件 md5 一致才复用，否则重下；**不带 md5**：缓存 3 天内有效 | `JarLoader.java:196-230`、`FileUtils.isWeekAgo`（实为 3 天） |
| R-CLI-05 | 顶层 `spider` 由 `downloadJarAsync` 用 OkHttp `Request.url(url)` 下载，只接受 http(s)；本地需先经 `fixContentPath` 转成 http 才可用 | `ApiConfig.java:438-458` |
| R-CLI-06 | `configUrl()`：`file://` → `clan://localhost/`；含 `;pk;` 时拆出密钥；`clan` 开头 → `clanToAddress`；其余非 http 前缀补 `http://` | `ApiConfig.java:170-192` |
| R-CLI-07 | `clanToAddress()`：`clan://localhost/<路径>` → `http://127.0.0.1:<端口>/file/<路径>`；端口默认 9978，被占用时递增 | `ApiConfig.java:1773-1781`、`ControlManager` |
| R-CLI-08 | `clanContentFix()`：仅当**配置 URL 以 `clan` 开头**时，把配置内容里的 `clan://localhost/`、`file://` 前缀替换成本机 http 基址 | `ApiConfig.java:383-393、1783-1786` |
| R-CLI-09 | `fixContentPath()`：仅当配置内容含 `"./` 或 `"../` 时执行；先替换 `../`，再替换 `./`；基准是**配置自身的 URL** | `ApiConfig.java:1788-1798` |
| R-CLI-10 | 本地文件服务：请求路径以 `/file/` 开头时，取其后半段拼到外部存储根，**不做 `..` 防穿越校验** | `RemoteServer.java:158-166` |
| R-CLI-11 | Python：插件名取 `url` 末段去扩展名；`file://` 前缀会被直接去掉，导致本地路径失效；**必须写 `./py/x.py`**；每次 init 都会重新下载 | `pyramid/src/python/app.py` |
| R-CLI-12 | `lives[].type` 只接受 `"0"`、`"3"`；其它值会导致直播分组被清空后直接返回 | `ApiConfig.java:1384-1387` |
| R-CLI-13 | 多线路索引只认 `{"urls":[{"url","name"}]}`（兼容纯字符串数组）；JSON 中含 `sites` 或没有 `urls` 时**不视为索引** | `ApiConfig.java:671-703` |
| R-CLI-14 | 识别到索引后自动加载第一条，并写入线路列表；直接加载子配置会因 `clearApiLinesIfUnmatched` 清空线路列表 | `ApiConfig.java:650-669、728-739` |
| R-CLI-15 | 客户端只有一份当前配置（`API_URL` 单键）；不同包不会同时并列显示，只能通过接口历史切换 | `HawkConfig.API_URL` |
| R-CLI-16 | 配置每次启动都尝试拉取，只有拉取失败才回退本地缓存 | `HomeActivity` 调用 `loadConfig(useCache=false)` |
| R-CLI-17 | 本地文件服务把请求路径**原样**拼到存储根，不做百分号解码；因此 `clan://localhost/<包>/SL 综合线路/api.json` 只能写中文原样，写成 `SL%20%E7%BB%BC...` 会 404，表现为「选了线路但站点为空」 | `RemoteServer.java:158-166`；可用本地包 `本地仓.txt` 全部写中文原样 |

【待验证】以下一项需实机确认，验证方法写在括号内：
1. `UriUtil.resolve(<含中文空格的配置URL>, "../")` 的返回值是否等价于「上一级目录」（临时把一条 jar 站点指向 `../_common/jar/` 的空壳 jar，看是否 200）。

（原第 2 项「NanoHTTPD 是否解码百分号」已由 R-CLI-17 定性为不解码，转为规则。）

## 3. 仓库架构与应用分层

### 3.1 目标结构

仓库从「只服务 TVBox」升级为「多应用」，外层增加应用层。**应用层只负责挂载，不改变任何应用内部的包结构**。

```text
<仓库根>/
├── README.md                      ← 本文件：仓库级通用标准
├── 声明.md
├── LICENSE
├── 发布说明.md
├── .gitignore
├── apps/
│   ├── 应用清单.csv                ← 应用登记表（唯一）
│   ├── tvbox/
│   │   ├── README.md              ← TVBox 应用标准（配置格式与加载机制）
│   │   └── packages/
│   │       ├── 包清单.csv
│   │       └── tvboxSL/           ← 包（= 手机本地父目录名）
│   ├── catvod/                    ← 预留：猫影视类
│   └── reader/                    ← 预留：阅读 / Legado 类
├── records/
│   ├── 探活索引.csv
│   ├── 冲突处置索引.csv
│   └── 2026-11-07/
│       └── tvbox/
│           ├── tvboxSL.json
│           ├── 探活报告-tvboxSL.md
│           └── 冲突处置-tvboxSL.md
└── _分析/                          ← 本地分析产物，.gitignore 排除
```

| 编号 | 规则 |
|---|---|
| R-ARC-01 | 应用必须落在 `apps/<应用id>/`，应用内必须自带 `README.md` 与 `packages/`；禁止把应用文件放到仓库根 |
| R-ARC-02 | 新增应用 = 新建 `apps/<应用id>/` + 在 `apps/应用清单.csv` 加一行；**不得改动既有应用** |
| R-ARC-03 | 新增包 = 新建 `apps/<应用id>/packages/<包id>/` + 在该应用 `包清单.csv` 加一行；**不得改动既有包** |
| R-ARC-04 | 包内一切引用只用相对路径；禁止跨包、跨应用引用（不写 `../../`、不写绝对域名） |
| R-ARC-05 | 应用 id：小写 ASCII，`[a-z][a-z0-9]{2,15}`；已有 `tvbox`，预留 `catvod`、`reader` |
| R-ARC-06 | 包 id：小写 ASCII，`[a-z][a-z0-9-]{2,19}`，同一应用内唯一；首个包固定 `tvboxSL` |
| R-ARC-07 | 线路代号（`std`/`kid`/`eld` 等）在同一包内唯一，用于站点 key 前缀；不同包可重复 |
| R-ARC-08 | 应用清单字段固定：`应用id,名称,状态,标准文档,包清单,入口格式,备注`；状态只允许 `planned`/`active`/`retired` |

### 3.2 文档分层

| 层级 | 文件 | 管什么 | 不管什么 |
|---|---|---|---|
| 仓库级 | 根 `README.md` | 定位、架构、命名总则、版本、门禁、探活、记录、验收、文档维护、条款对照 | 具体应用的配置字段语法 |
| 应用级 | `apps/<id>/README.md` | 该应用的配置格式、加载机制、入口写法、jar/js/py 差异 | 通用纪律（只引用，不重写） |
| 包级 | `apps/<id>/packages/<包id>/目录说明.txt` | 安装说明、当前版本状态 | 标准与规则 |

| 编号 | 规则 |
|---|---|
| R-ARC-09 | 一条规则只允许写一处；应用级文档引用条款号，不得复制正文 |
| R-ARC-10 | 应用级文档与仓库级冲突时，以仓库级为准；若应用确有例外，必须在仓库级第 17 章登记条款变更 |

### 3.3 应用扩展预留

| 应用 | 预留内容 | 现在能定的 | 必须等接入时再定 |
|---|---|---|---|
| `tvbox` | 已落地 | 全部 | — |
| `catvod`（猫影视类） | 目录 + 清单行 | 多仓入口同样是配置 URL，可复用「包内相对路径」思路 | 字段名、加密方式、是否需要独立索引 |
| `reader`（阅读/Legado） | 目录 + 清单行 | 导入物是书源/规则 JSON，不是 `api.json` | 书源 schema、校验方式、是否需要独立探活口径 |

`apps/应用清单.csv` 预留列：`入口格式` 取值示例 `api_index`（TVBox）、`multi_repo`（猫影视）、`book_source`（阅读）。未接入前只登记 `planned`，不建空目录。

## 4. 目录与命名

### 4.1 包内结构（以 `tvboxSL` 为例）

```text
apps/tvbox/packages/tvboxSL/
├── version.json                   ← 包 id、版本、状态、线路清单
├── api_index.json                 ← 在线入口：三条线路的绝对 URL
├── api_index_local.json           ← 本地入口：三条线路的 clan:// 地址
├── api_all.json                   ← 单文件全量（151 站），绝对 URL
├── 目录说明.txt                    ← 用户安装说明
├── _common/
│   ├── jar/                       ← 公共 jar（ASCII 文件名）
│   └── md5.txt                    ← jar 校验清单
├── SL 综合线路/                    ← 线路目录（中文含空格）
│   ├── api.json
│   ├── spider_std.jar
│   ├── js/  py/  open/  ext/  lib/
├── SL 少儿线路/
└── SL 长辈线路/
```

| 路径 | 用途 | 进版本库 | 客户端是否加载 |
|---|---|---|---|
| `version.json` | 包版本与线路登记 | 是 | 否 |
| `api_index.json` | 在线多线路入口（绝对 URL） | 是 | 是（作为配置地址） |
| `api_index_local.json` | 本地多线路入口（`clan://`，中文原样） | 是 | 是（整包拷到手机后使用） |
| `api_all.json` | 单文件全量配置（三线合一） | 是 | 是（不支持 `urls` 索引的客户端） |
| `目录说明.txt` | 给人看的安装说明 | 是 | 否 |
| `_common/jar/*.jar` | 跨线路共用的 jar | 是 | 是（被 `sites[].jar` 引用） |
| `_common/md5.txt` | jar 校验清单 | 是 | 否 |
| `<线路>/api.json` | 该线路唯一配置 | 是 | 是 |
| `<线路>/spider_<代号>.jar` | 顶层 `spider` 入口 | 是 | 是 |
| `<线路>/js/ py/ open/ ext/ lib/` | 该线路独占脚本与引擎 | 是 | 是（被 `api`/`ext` 引用） |
| `.gitkeep` | 占位空目录 | 是 | 否 |

### 4.2 命名规则

| 编号 | 对象 | 规则 | 示例 |
|---|---|---|---|
| R-NAM-01 | 仓库名 | ASCII，`SL-Sources`（覆盖多应用后不再用 `SL-TVBox-Sources`） | `SL-Sources` |
| R-NAM-02 | 线路目录 | 中文，`SL <线路名>线路`；**允许且仅允许一个半角空格**；全角空格、括号、`·` 禁用 | `SL 综合线路` |
| R-NAM-03 | 线路配置 | 固定 `api.json`，不得改名 | `api.json` |
| R-NAM-04 | 索引文件 | 固定 `api_index.json` | `api_index.json` |
| R-NAM-05 | 站点 key | 四段式 `<线路代号>_<形态>_<用途>_<短名>`；正则 `^(std|kid|eld)_(jar|js|py|cms)_(vod|live|tool)_[a-z0-9]{2,12}$`，总长 8–32 | `std_jar_vod_xingxing` |
| R-NAM-06 | 入口 jar | `spider_<线路代号>.jar` | `spider_std.jar` |
| R-NAM-07 | 公共 jar | `<来源>_<角色或内容hash8>.jar`，全 ASCII，禁中文/空格/括号 | `xingwei_main.jar`、`ouge_6f1e49c3.jar` |
| R-NAM-08 | 线路内脚本 | 保留原包相对位置；跨线路同名时加来源前缀，不得直接覆盖 | `api/fantaijing_drpy2.min.js` |
| R-NAM-09 | 图片 | 小写 ASCII + `.png`/`.jpg`；单文件 ≤200 KB；仅放该线路 `img/` | `logo_xingwei.png` |
| R-NAM-10 | 允许的线路内目录 | `js/ py/ open/ ext/ lib/ api/ img/ live/ config/`，只允许一层；禁止新增语义不明目录 | — |
| R-NAM-11 | 记录文件 | `records/<YYYY-MM-DD>/<应用id>/<包id>.json`、`探活报告-<包id>.md`、`冲突处置-<包id>.md` | — |
| R-NAM-12 | 版本目录 | 需要留存旧版时用 `v<主>.<次>.<修订>`，只出现于发布侧，不进包目录 | `v1.2.0` |

### 4.3 中文含空格路径的引用写法

磁盘目录名保持中文含空格（R-NAM-02）。**索引一律写中文原样，禁止百分号编码**（R-CLI-17）。

| 场景 | 写法 |
|---|---|
| 在线索引 | `https://raw.githubusercontent.com/<owner>/SL-Sources/main/apps/tvbox/packages/tvboxSL/SL 综合线路/api.json` |
| 本地索引 | `clan://localhost/tvboxSL/SL 综合线路/api.json` |
| 线路内引用 | `./js/x.js`、`./py/x.py`、`../_common/jar/x.jar` |

| 编号 | 规则 |
|---|---|
| R-NAM-13 | 索引里的线路地址：在线写绝对 raw URL、本地写 `clan://localhost/<包id>/<线路目录>/api.json`；两者都必须写中文原样，禁止 `%E7%BB%BC`、禁止 `./` 相对写法（相对写法依赖客户端解析，实测会失败） |
| R-NAM-14 | 线路内脚本引用写 `./js/x.js`、`./py/x.py`；公共 jar 写 `../_common/jar/x.jar`；不得写 `file://` |
| R-NAM-15 | 顶层 `spider` 写 `./spider_std.jar;md5;<32位小写>`；不得依赖 `clan://` |
| R-NAM-16 | 站点 `name`、`flags` 中禁止出现 `"./` 与 `"../` 字符序列（会被 `fixContentPath` 当路径替换）；`api`、`ext`、`jar` 反而**必须**用相对路径，由 `fixContentPath` 正常改写（R-NAM-14） |
| R-NAM-17 | 站点 `name` 清洗：去 emoji、去全角符号、去首尾空白；长度 2–10 字；清洗后撞名按第 13 章处理 |
| R-NAM-18 | 新增 CMS 源的 `name` 末尾写速度档位后缀：`-快`（实测 ≤1.5 s）、`-中`（1.5–4 s）、`-慢`（≥4 s）；档位取值只用这三个汉字，禁止 emoji、禁止自造档位 |
| R-NAM-19 | 速度档位以探活实测首字节/整包耗时为准，写入 `_分析/sources_builtIn.csv` 的「耗时ms」列；无实测数据的老站点不得凭印象标档位 |
| R-NAM-20 | 本地入口固定文件名 `api_index_local.json`，内容为 `clan://` 三条线路；在线入口固定 `api_index.json`，内容为绝对 URL；两者除 url 写法外必须完全一致 |
| R-NAM-21 | 单文件全量配置固定文件名 `api_all.json`，把三条线路 `sites` 合并；所有 `api`/`jar`/`ext` 一律写绝对 raw URL，`;md5;` 段不得编码；`key` 与线路内保持完全一致 |

**不满足的处理**：出现百分号编码的中文目录、`file://`、`"./` 冲突序列中任一项，该文件判不合格，不进入验收。

## 5. TVBox 配置格式（`api.json`）

### 5.1 必填与可选字段

| 字段 | 必填 | 取值与规则 |
|---|---|---|
| `spider` | 是 | `./spider_<代号>.jar;md5;<32位小写>`；骨架阶段允许空串 |
| `sites` | 是 | 数组，可为空；顺序即 UI 顺序 |
| `lives` | 是 | 数组，可为空 |
| `parses` | 是 | 数组，可为空 |
| `flags` | 是 | 字符串数组，可为空 |
| `wallpaper` | 否 | 图片 URL，留空 |
| `ijk` | 否 | 播放器选项，本仓不配置 |

### 5.2 `sites[]`

| 字段 | 必填 | 规则 |
|---|---|---|
| `key` | 是 | 符合 R-NAM-05；全配置唯一；禁用 `push_agent` |
| `name` | 是 | 清洗后 2–10 字（R-NAM-17）；新增 CMS 源带速度档位后缀（R-NAM-18） |
| `type` | 是 | `0`/`1`/`3`；CMS 实测返回 JSON 用 `1`，XML 用 `0`（见 R-CFG-09） |
| `api` | 是 | `type:3` 时：jar 写 `csp_<类名>` 或 `csp_<类名>;md5`（由 `jar` 决定载体）；js 写 `./...js`；py 写 `./py/x.py`。`type:0/1` 时写上游 CMS 地址 |
| `jar` | 视情况 | `type:3` 的 jar 站点必填，写 `../_common/jar/x.jar;md5;...`；不得为空 |
| `searchable` | 是 | `0`/`1`；列表型 CMS 才允许 `1` |
| `quickSearch` | 是 | `0`/`1`；未验证搜索能力一律 `0` |
| `changeable` | 否 | `0`/`1`，默认 `1`；`0` = 不参与详情页换源（`ApiConfig.java:767`） |
| `ext` | 否 | 短字符串；禁止路径序列（R-NAM-16）；禁止换行与首尾空白 |
| `playerType` | 否 | 与 `parses[].flag` 对应的播放器标记，不填即默认 |

> 站点级**没有** `filter` 字段：客户端只读 `searchable`、`quickSearch`、`changeable`、`filterable`（`ApiConfig.java:765-772`）。`filterable` 只写不读（无 `getFilterable` 调用点），写了无效，禁止用于表达其它含义。CMS 的分类筛选能力由上游 `?ac=list` 返回的 `class` 决定，不靠站点字段配置。

|---|---|---|
| `name` | 是 | 中文分组名 |
| `url` | 是 | m3u/txt 地址；只允许 http(s) |
| `type` | 是 | **只能是 `"0"` 或 `"3"`**（R-CLI-12） |
| `playerType` | 否 | 默认 `0` |
| `ext` | 否 | 仅 `type:"3"` 使用，指向 py 解析 |
| `ua` | 否 | 上游要求特定 UA 时填写 |

### 5.4 `parses[]` 与 `flags[]`

- `parses[]` 每项：`name`、`type`（`0` 嗅探 / `1` 解析）、`url`、`ext{flag,header}`。
- `flags[]` 写 `parse_<源>`、`m3u8_<源>`、`vip_<平台>` 三类命名族；`sites[].playerType` 必须能在 `flags` 或 `parses` 中找到对应。

### 5.5 格式与取值硬规则

| 编号 | 规则 |
|---|---|
| R-CFG-01 | 严格 JSON：无注释、无尾逗号、无 BOM；UTF-8 |
| R-CFG-02 | 禁止 `type:-1` 与 `key:"push_agent"` |
| R-CFG-03 | 禁止 `lives[].type` 取 `"0"`/`"3"` 以外的值 |
| R-CFG-04 | 所有 jar 引用必须带 `;md5;<32位小写十六进制>` |
| R-CFG-05 | 单个配置文件 ≤512 KB；脚本单文件 ≤1 MB |
| R-CFG-06 | 站点总数：单线路 ≤300；超出必须拆线或拆包 |
| R-CFG-07 | 同一 `api` 的站点不得重复出现（同源异名按第 13 章合并） |
| R-CFG-08 | `sites` 顺序：① jar 主力 ② js 主力 ③ py 主力 ④ CMS 备用 ⑤ 工具/解析；首个站点必须是该线路最稳定主力 |

## 6. 多线路与索引

### 6.1 索引结构

```json
{
  "urls": [
    { "name": "综合", "url": "./SL%20%E7%BB%BC%E5%90%88%E7%BA%BF%E8%B7%AF/api.json" },
    { "name": "少儿", "url": "./SL%20%E5%B0%91%E5%84%BF%E7%BA%BF%E8%B7%AF/api.json" },
    { "name": "长辈", "url": "./SL%20%E9%95%BF%E8%BE%88%E7%BA%BF%E8%B7%AF/api.json" }
  ]
}
```

| 编号 | 规则 |
|---|---|
| R-LIN-01 | 索引只能含 `urls` 数组；不得含 `sites`，否则不被识别（R-CLI-13） |
| R-LIN-02 | 每条必须有 `name` 与 `url`；`name` 即「线路选择」里显示的名字 |
| R-LIN-03 | 第一条必须是该包最稳定线路（加载即进入它） |
| R-LIN-04 | 线路显示名与线路目录中文一致：综合 / 少儿 / 长辈；不得同名重复 |
| R-LIN-05 | 索引内线路地址必须相对（`./`），编码按 R-NAM-13；不得写域名 |
| R-LIN-06 | 新增线路 = 新建线路目录 + 索引加一条 + `version.json` 加一条；不得改既有线路 |
| R-LIN-07 | 禁止让用户直接添加子线路 `api.json` 作为「多线路」用法：未先加载索引时会清空线路列表（R-CLI-14）；子配置仅作单线备用入口，需在说明中标明 |

**不满足的处理**：索引含 `sites`、第一条不可用、显示名重复，任一项命中则整包不发布。

## 7. 资源与公共库复用

### 7.1 结论

| 资源 | 位置 | 理由 |
|---|---|---|
| jar | 包内 `_common/jar/` | 跨线路唯一重复的大文件，共用可省约 11.9 MB；`JarLoader` 直接解析相对路径 |
| js | 各线路自己的 `js/`/`open/`/`lib/` | `JsLoader` 没有 `clan://` 分支，且剧本常带相对依赖，跨目录易断 |
| py | 各线路自己的 `py/` | Python 侧会剥掉 `file://`，只认 `./` 相对；且每次 init 重下，跨目录引用无收益 |
| 图片 | 各线路自己的 `img/` | 体积小，不值得共用 |

| 编号 | 规则 |
|---|---|
| R-RES-01 | 公共 jar 只放包内 `_common/jar/`；不得放仓库级共享目录，不得放线路目录 |
| R-RES-02 | 站点引用公共 jar 一律写 `../_common/jar/<文件>.jar;md5;<32位>` |
| R-RES-03 | 同一 jar 在包内只允许一份；确需两个版本时，另一份放需要它的线路目录内，不共享 |
| R-RES-04 | `_common/md5.txt` 必须登记每个 jar 的 md5、字节数与引用线路代号；未登记视为不合格 |
| R-RES-05 | jar 文件名全 ASCII；伪装成 `.jpg`/`.png` 的 jar 必须改名为 `.jar` 后在 `md5.txt` 备注原扩展名 |
| R-RES-06 | 公共 jar 内每个被 `api` 引用的类名必须真实存在；发布前逐个核对 |
| R-RES-07 | 未使用（无任何 `api` 引用）的 jar 不得留在 `_common/jar/` |

**不满足的处理**：R-RES-01/03/04 违反 → 整包不合格；R-RES-06 违反 → 对应站点下线。

## 9. 在线分发

### 9.1 托管取舍

| 渠道 | 角色 | 结论 |
|---|---|---|
| GitHub raw | 主源 | 采用；分支 `main`；支持 Range |
| Gitee raw | 国内镜像 | 采用；与 GitHub 同结构，同一份文件 |
| jsDelivr | 加速备选 | 可用但不作主源：`@main` 缓存不可控 |
| 网盘 | 整包下载与备份 | 采用；**默认不作配置源** |
| 网盘直链 | 条件可作为配置源 | 必须通过 9.3 四项体检 |

### 9.2 直链要求

| 编号 | 规则 |
|---|---|
| R-ONL-01 | 配置与 jar 的直链必须 200 或 302 到文件本体；不得是 HTML 落地页 |
| R-ONL-02 | 不得校验 Referer/Cookie；UA 必须容忍 `okhttp/3.15` |
| R-ONL-03 | 链接必须长期有效；带时效签名、需登录换取的链接不得作配置源 |
| R-ONL-04 | 入口地址必须指向包内 `api_index.json`；包内引用保持相对路径，换域名不改包 |
| R-ONL-05 | 在线与本地共用同一份文件；在线更新只允许覆盖同路径文件（见第 10 章） |
| R-ONL-06 | 每次发布同时更新 GitHub 与 Gitee；两者内容必须字节一致 |

### 9.3 网盘直链四项体检（全部通过才可作配置源）

| 项 | 做法 | 通过判据 |
|---|---|---|
| ① 直链性 | `curl -I <直链>` | 200/206，`Content-Type` 为 json/jar/octet-stream，非 `text/html` |
| ② 免鉴权 | 去掉 Referer、Cookie，改用 `okhttp/3.15` 重试 | 仍 200/206 |
| ③ 稳定性 | 生成链接 24 小时后再测 | 仍可用，无签名过期 |
| ④ 限速 | 连续下载 12 MB 公共 jar | 平均 ≥200 KB/s，无强制断流 |

任一项不通过：网盘仅作整包下载/备份渠道，不写进任何 `api.json` 或入口地址。

**不满足的处理**：R-ONL-01/02/03 违反 → 该渠道停用；R-ONL-06 不一致 → 当次发布作废。

## 10. 版本、校验与缓存

| 编号 | 规则 |

| R-VER-01 | 包版本 semver `主.次.修订`；新增/下架站点、换 jar、改线路结构均升**次**版本；仅修错别字升修订 |

## 12. 探活标准

### 12.1 分形态探法

| 形态 | 探什么 | 成功判据 | 判定上限 |
|---|---|---|---|
| CMS（`type` 0/1） | `<url>?ac=list`；失败再试 `<url>?ac=list&at=json` | 200 且可解析且分类数 ≥1 | 每对象 2 次 |
| jar（`type:3`） | 不做网络探活；静态检查：文件存在、含 `classes.dex`、被引用类名存在 | 三项全过 | 静态 |
| js（`type:3`） | 剧本 URL | 200、≥5 KB、文件头不是 `<html` | 每对象 2 次 |
| py（`type:3`） | 剧本 URL | 200、非 HTML 落地页 | 每对象 2 次 |

### 12.2 执行口径

| 编号 | 规则 |
|---|---|
| R-PRB-01 | 连接超时 5 s、读取超时 10 s；总耗时上限 10 s/次 |
| R-PRB-02 | 每对象最多 2 次请求；相邻请求间隔 ≥1 s；单对象单次维护 ≤3 个请求 |
| R-PRB-03 | 只打列表/分类接口；不打搜索、不打详情、不下载播放地址 |
| R-PRB-04 | 不并发轰炸同一上游；同一域名下对象串行 |
| R-PRB-05 | UA 固定 `okhttp/3.15`，与客户端一致 |
| R-PRB-06 | 失败不追加第三次；连续两次失败即停 |

### 12.3 四档结论与死亡判定

| 结论 | 判据 |
|---|---|
| 可用 | 两次均成功，或一次成功且响应完整 |
| 间歇 | 一次成功一次失败；或成功但字节数明显异常（<1 KB） |
| 不可用 | 两次均失败，且有明确证据：DNS 失败、连接被拒、404/410、持续 5xx、返回 HTML 落地页 |
| 无法判定 | 无有效探测入口（纯 jar）、或响应为空但无错误 |

| 编号 | 规则 |
|---|---|
| R-PRB-07 | 判「上游死亡」需同时满足：连续两个维护周期（间隔 ≥24 h）均失败 + 错误类型属于 DNS/域名过期/TLS/404/410/持续 5xx |
| R-PRB-08 | 单次 502/超时/0 字节只判「间歇」，不得据此判死 |
| R-PRB-09 | 纯 jar 包没有 CMS 入口，只能记「无法判定」；不得写成「不可用」 |
| R-PRB-10 | 探活记录字段固定：包 id、包版本、对象名、形态、探测接口、HTTP 码、耗时 ms、字节数、分类数、重试次数、结论、证据摘要、探测时间、探测器版本 |
| R-PRB-11 | 每次维护必须产出三件：原始 `json`、人读 `探活报告-<包id>.md`、`探活索引.csv` 追加一行 |
| R-PRB-12 | 记录目录按「日期 → 应用 → 包」三层：`records/<YYYY-MM-DD>/<应用id>/<包id>.json` |
| R-PRB-13 | 探活索引列固定：`日期,应用id,包id,包版本,对象总数,可用,间歇,不可用,无法判定,新增失效,恢复,报告路径,原始数据路径` |
| R-PRB-14 | 记录默认全部保留；超过 12 个月的原 json 移入 `records/_归档/<年>/`，索引行不删 |
| R-PRB-15 | 探活范围覆盖**所有包的配置内站点**，不只新接入的来源 |

**不满足的处理**：缺任一记录件、结论与证据矛盾、把「无法判定」写成「可用」，该次维护判不合格，不得发布。

## 13. 修复、回归与冲突处置

### 13.1 结构可修与不可修

| 类型 | 现象 | 可修 | 修法 |
|---|---|---|---|
| 缺 md5 | jar 引用无 `;md5;` | 是 | 计算 md5 补写，更新 `md5.txt` |
| `lives.type` 非法 | 不是 `"0"`/`"3"` | 是 | 按上游实际形态改为合法值 |
| 引擎被替换 | js 引擎文件实为 HTML 错误页 | 是 | 换回正确引擎文件或改用同线可用引擎 |
| key 重复 | 同配置内 key 相同 | 是 | 加线路/来源前缀消歧 |
| 路径错误 | `../` 乱用、相对路径断 | 是 | 改为 `./` 或 `../_common/` |
| jar 缺失 | 引用文件不存在 | 是 | 补文件或改指向同内容 jar |
| 上游死亡 | DNS 失败、域名过期、404 持续 | 否 | 只下架，不伪造 |
| 需鉴权/付费 | 播放需登录、充值、扫码 | 否 | 只标注/下架，不绕鉴权 |
| 载体非配置 | 下载物是图片、网页、说明文字 | 否 | 记录证据，不进候选 |

| 编号 | 规则 |
|---|---|
| R-REP-01 | 修复只做结构层；不得伪造上游响应、不得绕鉴权、不得改上游数据 |
| R-REP-02 | 每条修复必须写「现象 → 根因 → 修法 → 验证方式」四段，缺一段不算修复完成 |
| R-REP-03 | 修完必须复探一次；复探结论与修复前不同的，在记录中写清前后对比 |
| R-REP-04 | 不可修项只下架并留证，不从候选清单中删证据 |

### 13.2 重复与冲突处置

重合度定义：上游归一化为 `scheme://host/path`（去 query、小写、去尾斜杠），对 key 集合与上游集合分别求 Jaccard，取较大值；站点名去 emoji/空格后小写仅作人工复核辅助。

| 编号 | 场景 | 判定 | 处置 | 留痕 |
|---|---|---|---|---|
| C1 | 两条线路高度重合 | 重合度 ≥60%，或同名同源 | 保留站点多、可用率高者为主线；另一条独占站点补入并标 `·备线` | 重合率、保留方、补入清单 |
| C2 | 两条线路部分重合 | 30% ≤ 重合度 < 60% | 允许并存；重复站点只留一份 | 重合率、去重数 |
| C3 | 同站点跨线路，key 相同 | 全局 key 去重 | 保留一份；两线都要用则改线路前缀 | key、涉及线路 |
| C4 | 同站点跨线路，key 不同 | 归一化上游相同 | 同源异名：留被引用多者，并列留探活更好者 | 三方对照 |
| C5 | 同源异名 | C4 判定 | 只留一个，名称取更规范者 | 同上 |
| C6 | 同名异源 | 名称归一化相同、上游不同 | 都可用则都留，名称加 `·<来源>`；只有一个可用则删另一个 | 两上游与结论 |
| C7 | 同 jar 多版本 | 按 md5 分组 | `_common` 只留一个；另一版本放需要的线路目录内 | md5、所属线路 |
| C8 | 索引重复线路/重名 | 解析后 url 去重、name 去重 | 去重；重名加 `·2`；3 条以上重复阻断发布 | 原始索引片段 |
| C9 | 新旧包并存 | 同一时刻只有一份当前配置（R-CLI-15） | 不视为冲突；key 带线路代号防串号 | 包清单登记 |
| C10 | 名称含 emoji/特殊符号 | 清洗后撞名 | 加来源后缀，仍撞加 `·2`；key 不含特殊字符 | 原名→新名 |
| C11 | 同域不同路径 | 归一化到完整 path | 视为不同站点；内容相同则按 C4 | path 与对比结论 |
| C12 | 版本未变内容变了 | 比对 md5 清单 | 阻断发布，升版本并更新 md5 | 差异文件清单 |
| C13 | jar 被多线共用 | 正常 | 不处置，`md5.txt` 登记全部引用线 | 自动登记 |
| C14 | 清洗后名称为空 | 长度 0 | 用 key 的短名生成，或剔除 | 原名与处置 |

| 编号 | 规则 |
|---|---|
| R-REP-05 | 同一规则冲突时优先级：同名同源 > 探活结论 > 站点数量 > 名称规范度 |
| R-REP-06 | 每次处置必须在 `records/<日期>/<应用id>/冲突处置-<包id>.md` 留痕，并在 `冲突处置索引.csv` 追加一行 |

## 14. 验收标准

判定人：`自动` = 脚本可判；`人工` = 必须装客户端确认。两项均需在工作记录中签字。

### 14.1 单线路验收（12 项）

| 编号 | 检查项 | 判定方式 |
|---|---|---|
| A01 | `api.json` 可被严格 JSON 解析，无 BOM/注释/尾逗号 | 自动 |
| A02 | `spider`/`sites`/`lives`/`parses`/`flags` 齐全 | 自动 |
| A03 | 所有 key 合规、唯一、无 `push_agent` | 自动 |
| A04 | 所有 jar 引用带 md5，文件存在且 md5 一致 | 自动 |
| A05 | 所有被引用脚本文件存在、非 HTML | 自动 |
| A06 | `lives[].type` 仅 `"0"`/`"3"` | 自动 |
| A07 | `name`/`flags` 无 `"./`、`"../` 序列（`api`/`ext`/`jar` 除外） | 自动 |
| A08 | 成人词表与域名扫描 0 命中 | 自动 |
| A09 | 网盘正则扫描 0 命中 | 自动 |
| A10 | 站点名清洗后无重复、长度合规 | 自动 |
| A11 | 实机抽 3 个站点：首页有分类、首个分类有内容 | 人工 |
| A12 | 实机抽 1 个站点：能起播 | 人工 |

### 14.2 整包验收（10 项）

| 编号 | 检查项 | 判定方式 |
|---|---|---|
| B01 | 三条线路均通过单线路验收 | 自动 + 人工 |
| B02 | 索引可被识别，加载后自动进入第一条 | 人工 |
| B03 | 「线路选择」列出全部线路，切换后站点整份更换 | 人工 |
| B04 | 跨线路 key 无重复、无收藏串号 | 自动 |
| B05 | 重合度已计算并登记（无 ≥60% 未合并项） | 自动 |
| B06 | 本次探活记录三件齐全，索引已追加 | 自动 |
| B07 | `version.json` = `包清单.csv` = `发布说明.md` | 自动 |
